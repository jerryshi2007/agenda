> 所属产品：[家庭日程协作工具](index.md)

## 1. 模块概述

打卡与统计是日程管理模块的下游模块，负责定义打卡时间规则、统计完成数据、为家长和孩子提供数据看板，以及通过微信订阅消息进行日程提醒。

**核心能力：**

- 打卡时间窗口（提前打卡、逾期判定、三种类型差异化规则）
- 双维度连续完成统计（单一日程连续 + 整体连续天数）
- 按周/月的完成率统计（排除已取消日程）
- 家长端数据看板（完成率 + 连续天数 + 趋势，多孩子可切换并列）
- 孩子端"我的统计"（完成率 + 连续天数 + 成就徽章，可回溯历史）
- 微信订阅消息提醒（日程开始前提醒 + 作业任务截止提醒）

**与其他模块的关系：**

- 日程管理：打卡交互（按钮、状态、打卡/撤销）在 `module-event.md` 定义，本文档引用；打卡时间窗口规则由本文档定义
- 家庭管理：统计以家庭 + 孩子为维度，孩子展示模式不影响统计计算逻辑
- 认证与账户：JWT 携带用户身份，统计 API 按角色（家长/孩子）返回不同数据
- 孩子展示模式：各模式下孩子端统计展示的差异由 [孩子展示模式模块文档](module-display-mode.md) 定义（如小学模式仅展示本周完成率、高年级模式展示完整个人统计），本文档仅定义统计计算的**逻辑规则**

### 1.1 分期范围

> 注：打卡与统计的完整能力分两期上线。首期聚焦打卡规则与结算，二期上线统计看板与成就徽章。

## 2. 打卡时间窗口

### 2.1 概述

打卡交互（按钮点击、状态切换）已在 [日程管理模块文档 §10](module-event.md#10-打卡与状态) 和 [§8.4](module-event.md#84-打卡按钮交互逻辑) 定义。本节定义打卡的**时间边界规则**——什么时间范围内可以打卡、何时触发逾期/已结束判定。

### 2.2 提前打卡

**规则**：允许在日程开始时间前 **30 分钟**内提前打卡。

| 条件 | 打卡按钮状态 |
|------|-------------|
| 当前时间 < 开始时间 - 30 分钟 | 灰色不可点击，显示"X 分钟后可打卡" |
| 当前时间 ≥ 开始时间 - 30 分钟 | 可点击，正常打卡 |
| 当前时间 ≥ 开始时间 | 可点击，正常打卡 |

**示例**：钢琴课 16:00 开始，15:30 起即可打卡。15:29 时按钮灰色。

**适用范围**：三种类型均适用此规则。

### 2.3 逾期判定

三种类型的逾期/已结束判定时机各不相同：

| 日程类型 | 逾期/已结束状态 | 判定时机 | 示例 |
|---------|:--:|------|------|
| 课后活动 | 已结束 | 结束时间 + **2 小时**后仍未打卡 | 钢琴课 16:00-17:00，19:00 时仍未打卡 → 已结束 |
| 日常作息 | 未完成 | 当天 **24:00** 结算，次日凌晨仍未打卡 | 练琴 16:00-16:30，当天 24:00 前可打卡，次日 0:00 → 未完成 |
| 作业任务 | 逾期未完成 | 截止日期当天 **24:00** 仍未打卡 | 截止 10 月 27 日，10 月 28 日 0:00 → 逾期未完成 |

**设计要点：**

| 要点 | 说明 |
|------|------|
| 课后活动 2 小时缓冲 | 覆盖"接孩子回家 + 吃饭 + 想起来打卡"的时间窗口 |
| 日常作息当天结算 | 在家做的事，当天内补打卡都是合理的 |
| 作业任务无缓冲 | 截止日期就是截止日期，模糊缓冲会削弱"截止"概念 |

### 2.4 逾期后是否可补打卡

逾期后**不可补打卡**。已结束/未完成/逾期未完成是终态，如需补救需家长手动操作（如编辑日程或联系技术支持）。

| 状态 | 可打卡？ | 显示 |
|------|:--:|------|
| 未完成（进行中） | ✓ | 正常打卡按钮 |
| 已结束 | ✗ | 灰色"已结束"，无按钮 |
| 未完成（终态） | ✗ | 红色"未完成"，无按钮 |
| 逾期未完成 | ✗ | 红色"逾期未完成"，无按钮 |
| 已取消 | ✗ | 灰色"已取消"，无按钮 |

## 3. 连续完成统计

### 3.1 统计范围

连续完成统计**仅适用于日常作息**类型。课后活动和作业任务不参与连续完成计算。

**理由**：
- "连续打卡"的心理激励来自"每天坚持做一件事"，这正是日常作息的核心场景
- 课后活动是外部固定安排，连续出席更多是"没请假"而非"主动坚持"
- 作业任务是一次性的，没有"连续"概念

### 3.2 双维度定义

连续完成统计包含两个独立维度：

| 维度 | 含义 | 示例 | 适用场景 |
|------|------|------|---------|
| **单一日程连续** | 同一日程每个实例连续完成的天数 | "练琴"连续 15 天、"阅读"连续 8 天 | 激励孩子坚持某一件具体的事 |
| **整体连续天数** | 每天至少完成 1 项日常作息即为连续 | 周一练琴、周二阅读、周三练琴 = 连续 3 天 | 衡量"每天都有在做事"的整体习惯 |

两个维度各自独立计算，互不影响。

### 3.3 中断规则

| 事件 | 是否中断连续 | 理由 |
|------|:--:|------|
| 未打卡（逾期） | **中断** | 逾期意味着过了当天还没打卡，本质上就是"没完成" |
| 已取消 | **不中断** | 取消是家长主动操作（孩子生病、老师请假），不是孩子没坚持 |
| 未打卡（当天尚未结束） | **不中断** | 当天还有机会打卡，结算时再判定 |

### 3.4 计算时机

- 连续天数在**每天结算时**（次日凌晨）更新
- 结算逻辑：遍历昨日所有日常作息实例 → 判断是否中断 → 更新连续计数
- 前端实时展示当前连续天数（含今天尚未结算的实例，如果今天已打卡则计入）

### 3.5 单一日程连续示例

```
"练琴"日程：周一~周五 16:00-16:30

周一 ✓ 打卡  → 连续 1 天
周二 ✓ 打卡  → 连续 2 天
周三 ✗ 取消（生病） → 连续 2 天（不中断）
周四 ✓ 打卡  → 连续 3 天
周五 ✗ 未打卡 → 连续 0 天（中断，重新开始）
```

### 3.6 整体连续示例

```
周一：练琴 ✓、阅读 ✓  → 当天至少完成 1 项 ✓ → 整体连续 1 天
周二：练琴 ✓、阅读 ✗  → 当天至少完成 1 项 ✓ → 整体连续 2 天
周三：练琴 ✗、阅读 ✗  → 当天 0 项完成       → 整体连续 0 天（中断）
周四：练琴 ✗、阅读 ✓  → 当天至少完成 1 项 ✓ → 整体连续 1 天
```

## 4. 完成率统计

### 4.1 计算公式

```
完成率 = 已完成数 / (总日程数 - 已取消数) × 100%
```

- **分子**：已完成打卡的日程实例数
- **分母**：所有应完成的日程实例数（排除已取消，三种类型均纳入）
- 已取消不参与计算——取消是家长主动操作，不应拉低完成率

**分母为 0 时**：当总日程数 - 已取消数 = 0（所有日程均被取消），完成率显示"--"（不适用），提示"本周暂无有效日程"。

### 4.2 时间粒度

支持按**周**和按**月**两个粒度：

| 粒度 | 计算范围 | 默认 |
|------|---------|:--:|
| 本周 | 周一 ~ 周日 | 是 |
| 本月 | 1 日 ~ 月末 | -- |

**设计要点**：
- 日粒度不做——某一天通常只有 1-2 项日程，完成率非 0% 即 100%，信息量低
- 周是家长管理日程的自然周期（课外班按周排），月适合看整体趋势

### 4.3 按孩子独立计算

每个孩子的完成率独立计算，不合并。多孩子家庭中，每个孩子有各自的完成率数值。

### 4.4 按类型拆分

完成率在看板中可下钻按类型查看：

| 拆分维度 | 说明 |
|---------|------|
| 全部 | 默认视图，三种类型汇总 |
| 课后活动 | 仅课后活动类的完成率 |
| 日常作息 | 仅日常作息类的完成率 |
| 作业任务 | 仅作业任务类的完成率 |

### 5.3 多孩子展示

| 条件 | 展示方式 |
|------|---------|
| 1 个孩子 | 不显示孩子切换栏，直接展示该孩子数据 |
| 2-3 个孩子 | 默认并列展示指标卡片，上方 Tab 可切换只看某一个 |

| 指标 | 说明 | 附属信息 |

| 视图 | 横轴 | 每根柱子 |

| 本周 | 周一 ~ 周日 | 当天完成率 |

柱子颜色：完成率 ≥ 80% 绿色，50%-80% 橙色，< 50% 红色。

### 5.6 连续完成明细

列出当前孩子所有日常作息日程的连续完成天数，按天数降序排列。显示形式为进度条 + 天数数字。

### 6.3 月度回溯

- 孩子可左右滑动或点击箭头切换月份，查看历史数据
- 历史月份展示完成率趋势（每周一根柱子）和当月获得的徽章
- 不限制可回溯的月份数量

### 6.4 成就徽章

#### 6.4.1 徽章体系

首期提供基于**单一日程连续天数**的基础徽章：

| 徽章 | 解锁条件 | 图标 | 说明 |
|------|---------|:--:|------|
| 一周坚持 | 任一日程连续 7 天 | 🏆 | 坚持一周了！ |
| 两周达人 | 任一日程连续 14 天 | ⭐ | 两周不间断！ |
| 一月之星 | 任一日程连续 30 天 | 🌟 | 坚持一个月！ |
| 百日之星 | 任一日程连续 100 天 | 👑 | 百天里程碑！ |

#### 6.4.2 徽章展示

- 已解锁：彩色图标 + 天数 + "已获"
- 未解锁：灰色图标 + 天数 + 进度条（如"30 天 · 已完成 12/30"）
- 新解锁时弹出庆祝动画，点击关闭后不再重复

#### 6.4.3 设计决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 徽章维度 | 仅单一日程连续 | 整体连续天数不适合做徽章（"每天至少做一件事"门槛太低） |
| 徽章数量 | 首期 4 个 | 覆盖短期到长期激励，不堆砌 |
| 完整成就系统 | 第三期 | 首期验证基础徽章效果后再扩展 |

## 7. 订阅消息提醒

### 7.1 概述

通过微信小程序订阅消息能力，在日程开始前向用户推送提醒。首期专注于"日程开始前提醒"和"作业任务截止提醒"两种场景。

### 7.2 提醒类型

| 提醒类型 | 触发时机 | 订阅方式 | 可配置 |
|---------|---------|---------|:--:|
| 日程开始前提醒 | 课后活动/日常作息开始前 N 分钟 | 用户主动订阅 | ✓ |
| 作业截止前一天 | 截止日期前一天早上 9:00 | 用户主动订阅 | ✗ |
| 作业截止当天 | 截止日期当天早上 9:00 | 用户主动订阅 | ✗ |

### 7.3 提醒时间配置

| 配置项 | 默认值 | 可选项 |
|--------|:--:|------|
| 开始前提醒提前量 | 30 分钟 | 15 分钟 / 30 分钟 / 60 分钟 |

- 配置入口：家长端"我的"→"设置"→"提醒设置"
- 配置对所有日程统一生效，不按单个日程设置
- 作业任务提醒时间为固定 9:00，不可配置

### 7.4 提醒对象

家长和孩子**各自独立订阅**，互不影响：

| 角色 | 可订阅 | 典型场景 |
|------|--------|---------|
| 家长 | 所有日程的提醒 | 提醒送孩子去上课、督促孩子完成作息 |
| 孩子 | 所有日程的提醒 | 提醒自己该练琴了、该做作业了 |

**设计要点**：
- 学龄前孩子的微信通常由家长代为操作，家长可帮孩子订阅
- 孩子端是否展示"提醒设置"入口，取决于孩子展示模式（高年级模式可自主设置）

### 7.5 订阅流程

```
┌──────────────────────────────────────┐
│  用户首次进入小程序                   │
│         ↓                            │
│  系统调用 wx.requestSubscribeMessage │
│  弹出微信原生订阅弹窗                  │
│  列出可订阅的消息模板                  │
│         ↓                            │
│  用户选择"允许" / "取消"              │
│         ↓                            │
│  系统记录订阅状态                     │
│         ↓                            │
│  后续可在"设置"中修改订阅偏好          │
└──────────────────────────────────────┘
```

### 7.6 消息模板

需在微信公众平台申请订阅消息模板。首期需要 2 个模板：

| 模板 | 用途 | 模板关键词 |
|------|------|-----------|
| 日程提醒 | 课后活动/日常作息开始前提醒 | 日程名称、开始时间、备注 |
| 作业截止提醒 | 作业任务截止提醒 | 任务名称、截止日期 |

### 7.7 推送策略

| 策略 | 规则 |
|------|------|
| 仅推送已订阅用户 | 未订阅不推送 |
| 仅推送未取消的日程 | 已取消日程不推送 |
| 仅推送未打卡的日程 | 已打卡日程不推送（无需再提醒） |
| 每个日程每次仅推送一次 | 不重复推送 |

### 7.8 异常处理

| 场景 | 处理方式 |
|------|---------|
| 用户拒绝订阅 | 不推送，用户可在设置中重新开启 |
| 订阅次数用完 | 微信限制每个模板有订阅次数上限，用完后需用户重新订阅 |
| 推送失败 | 静默失败，不重试，不影响日程正常使用 |
| 微信后台审核未通过 | 提醒功能暂不上线，先上线打卡统计，待模板审核通过后补上 |

## 8. 结算机制

### 8.1 每日结算

每天凌晨执行结算任务，处理前一天所有未打卡日程的状态变更：

| 日程类型 | 结算逻辑 |
|---------|---------|
| 课后活动 | 结束时间 + 2 小时后仍未打卡 → 状态变更为"已结束" |
| 日常作息 | 当天 24:00 仍未打卡 → 状态变更为"未完成" |
| 作业任务 | 截止日期当天 24:00 仍未打卡 → 状态变更为"逾期未完成" |

### 8.2 连续天数更新

结算同时更新连续完成天数：

- 遍历每个孩子的日常作息日程
- 按中断规则判定是否连续
- 更新单一日程连续天数和整体连续天数

### 8.3 徽章检测

结算完成后检测是否有新徽章解锁。如有，下次用户打开小程序时展示庆祝动画。

## 9. 边界与异常

覆盖空值、越界、并发、失败回退等异常场景，按四类组织。

### 9.1 输入与数据边界

| # | 场景 | 边界条件 | 预期行为 |
|---|------|---------|---------|
| BE-01 | 家庭无任何日程 | 首次使用，无日程数据 | 数据看板显示空态："还没有日程，去创建吧～"；我的统计显示空态 |
| BE-02 | 孩子无日常作息 | 孩子仅有课后活动和作业任务 | 连续天数显示"0"，连续完成明细列表显示空态"尚无日常作息日程，连续完成统计暂不可用" |
| BE-03 | 本周无任何有效日程 | 所有日程均被取消 | 完成率显示"--"，提示"本周暂无有效日程" |
| BE-04 | 完成率分母为 0 | 总日程数 = 已取消数 | 完成率显示"--"，提示对应时间范围内无有效日程 |
| BE-05 | 多端同时打卡 | 家长和孩子同时点击打卡 | 以首次打卡请求为准（数据库层面防重），后续请求返回"已完成"（幂等处理） |
| BE-06 | 跨天打卡 | 客户端时间与服务器时间差异 | 以服务器时间为准判定时间窗口，不依赖客户端时间 |
| BE-07 | 提醒提前量设为 15 分钟但日程已开始 | 日程 16:00 开始，提醒设为 60 分钟，但当前已 15:31 | 不推送该日程（提醒时间已过） |

### 9.2 状态与生命周期边界

| # | 场景 | 预期行为 |
|---|------|---------|
| BE-08 | 已取消日程恢复后打卡 | 恢复后状态回退为"未完成"，可正常打卡，打卡记录正常计入统计 |
| BE-09 | 已取消日程恢复后不回溯修改历史统计 | 历史统计（如之前的周完成率）保持不变，恢复仅影响当前和未来的统计周期 |
| BE-10 | 编辑日程时间（如修改开始时间） | 历史实例统计不受影响，仅影响未来实例 |
| BE-11 | 删除日程 | 历史打卡记录保留（数据完整性），已删除日程不参与后续统计 |
| BE-12 | 孩子从家庭移除 | 该孩子的历史统计保留（可查询），但不再更新。其他孩子的统计不受影响 |
| BE-13 | 日程的重复结束日期已到 | 该日程的历史统计数据保留，不再生成新的待打卡实例 |

### 9.3 网络与系统异常

| # | 场景 | 预期行为 |
|---|------|---------|
| BE-14 | 看板数据加载失败 | 显示错误提示"加载失败，下拉重试"。保留上次成功加载的缓存数据作为兜底展示 |
| BE-15 | 结算任务执行失败（部分数据） | 错误日志记录 + 重试（最多 3 次）。已成功结算的数据不变（幂等）。不影响其他孩子 |
| BE-16 | 推送消息服务不可用 | 静默失败，记录日志，不重试，不影响日程正常使用 |
| BE-17 | 订阅消息模板被微信下架 | 前端隐藏提醒设置入口，已订阅用户静默失效。待模板重新审核通过后恢复 |

### 9.4 并发与数据一致性

| # | 场景 | 预期行为 |
|---|------|---------|
| BE-18 | 结算任务执行中用户尝试打卡 | 打卡请求正常处理，结算任务仅处理前一天的数据，不影响当天正在进行中的打卡 |
| BE-19 | 多个孩子的结算任务同时执行 | 每个孩子独立结算，互不影响。并发执行时保证数据一致性（按孩子维度加锁或使用数据库事务） |
| BE-20 | 撤销打卡与结算竞态 | 用户在 23:59:50 撤销已打卡日程，次日 00:05 结算任务触发 → 以实例最终状态（撤销后=未完成）为准，结算任务正常将其变更为终态。不产生竞态错误。详见 US-CHK-27 |
| BE-21 | 鉴权失败打卡 | JWT 过期或非法用户尝试打卡 API → 返回 401，前端拦截器统一处理跳登录 |
| BE-22 | 日程时间被编辑后打卡记录有效性 | 日程开始时间从 16:00 改为 17:00，15:30 的打卡记录仍保持有效（打卡记录以打卡时的服务器时间为准，日程编辑仅影响未来实例，历史实例不受影响） |

## 10. 用户故事与验收标准（GWT 补充）

> 2026-08-08 结构化补充：将 §2–§8 的功能细化为 27 个用户故事（US-CHK-01~27），显式标注优先级（Must/Should/Could）并补充边界异常场景。正文功能描述以 §2–§8 为权威定稿，本章为可验证验收标准的补充，不重复正文内容。

### 10.1 打卡时间窗口（Must）

#### US-CHK-01：提前打卡窗口（Must）

- **Given** 一个课后活动日程"钢琴课"，开始时间 16:00，当前时间为 15:31
- **When** 用户查看该日程详情页
- **Then** 打卡按钮可点击，用户可正常打卡（当前时间 >= 开始时间 - 30 分钟）
- **Given** 当前时间为 15:29
- **When** 用户查看该日程详情页
- **Then** 打卡按钮灰色不可点击，显示"2 分钟后可打卡"
- **Given** 当前时间 >= 16:00
- **When** 用户查看该日程详情页
- **Then** 打卡按钮可点击，正常打卡

#### US-CHK-02：课后活动逾期判定（Must）

- **Given** 课后活动"游泳课"已结束（结束时间 17:00），当前时间为 18:30
- **When** 用户查看该日程详情页
- **Then** 打卡按钮仍可点击（结束时间 + 2 小时 = 19:00，尚未逾期）
- **Given** 当前时间为 19:01，日程仍未打卡
- **When** 用户查看该日程详情页
- **Then** 状态变为"已结束"，打卡按钮消失。显示灰色"已结束"文案
- **Given** 当前时间为 17:30，用户已完成打卡
- **When** 用户查看该日程详情页
- **Then** 显示绿色"已完成"，不触发逾期判定

#### US-CHK-03：日常作息逾期判定（Must）

- **Given** 日常作息"练琴"（当天 16:00-16:30），当前时间为当天 23:00，未打卡
- **When** 孩子查看该日程
- **Then** 打卡按钮仍可点击（当天 24:00 前均可打卡）
- **Given** 次日凌晨 0:01，前一天未打卡，结算任务已执行
- **When** 用户查看前一天的"练琴"日程
- **Then** 状态变为"未完成"（终态），打卡按钮消失，显示红色"未完成"

#### US-CHK-04：作业任务逾期判定（Must）

- **Given** 作业任务"数学练习册"，截止日期为 10 月 27 日，当前时间为 10 月 27 日 22:00，未打卡
- **When** 孩子查看该任务
- **Then** 打卡按钮仍可点击（当天 24:00 前均可打卡）
- **Given** 当前时间为 10 月 28 日 0:01，结算任务已执行
- **When** 用户查看该任务
- **Then** 状态变为"逾期未完成"，打卡按钮消失，显示红色"逾期未完成"

#### US-CHK-05：逾期后不可补打卡（Must）

- **Given** 一个日程实例处于终态（已结束/未完成/逾期未完成）
- **When** 用户查看该实例详情页
- **Then** 不显示任何打卡按钮，仅显示对应终态文本（灰色"已结束"/红色"未完成"/红色"逾期未完成"）
- **Given** 家长想为逾期日程补救
- **When** 家长尝试使用编辑功能修改该实例
- **Then** 历史实例的时间不可编辑到未来，如需补救需家长手动操作（编辑日程或联系技术支持）

#### US-CHK-27：撤销打卡与时序规则（Must）

- **Given** 用户已对日程"练琴"完成打卡（状态：已完成），当前时间仍在打卡时间窗口内（当天 24:00 前）
- **When** 用户在详情页点击"撤销打卡"
- **Then** 状态恢复为"未完成"，打卡记录删除。用户可重新打卡，重新打卡受时间窗口规则约束
- **Given** 结算任务已执行（次日凌晨），前一天"练琴"已变为终态"未完成"
- **When** 用户查看前一天"练琴"的详情页
- **Then** "撤销打卡"按钮不显示（终态日程不可撤销）。仅显示状态文字"未完成"（红色）
- **Given** 用户在 23:59:30 打卡，23:59:50 撤销，次日 00:05 结算任务触发
- **When** 结算任务遍历该日程实例
- **Then** 以实例最终状态为准——该实例当前为"未完成"（撤销后），结算任务正常将其变为终态"未完成"。不产生竞态错误
- **Given** 用户对课后活动"游泳课"完成打卡，当前时间已超过结束时间 + 2 小时（逾期窗口关闭）
- **When** 用户查看该日程详情页
- **Then** "撤销打卡"按钮不显示，状态变为"已结束"终态。逾期后不可撤销
- **Given** 用户撤销打卡后想重新打卡，但此时已超过打卡时间窗口（如日常作息已过当天 24:00）
- **When** 用户点击打卡按钮
- **Then** 返回"打卡窗口已关闭"，不可重新打卡。撤销操作不可逆

#### US-CHK-06：跨天打卡以服务器时间为准（Must）

- **Given** 孩子手机时间为 23:59，服务器时间为次日 00:01，日程"练琴"尚未打卡
- **When** 孩子点击打卡按钮
- **Then** 以服务器时间为准判定时间窗口。若服务器时间已过 24:00，打卡请求返回"打卡窗口已关闭"，打卡失败
- **Given** 客户端时间与服务器时间偏差超过 5 分钟
- **When** 用户执行打卡操作
- **Then** 前端使用服务器返回的实际打卡时间展示，不依赖客户端时间

### 10.2 连续完成统计（Should）

> 连续完成统计仅适用于日常作息类型，包含单一日程连续和整体连续天数两个维度。

#### US-CHK-07：查看单一日程连续天数（Should）

- **Given** 孩子"小明"有日常作息"练琴"，周一至周五每天。本周一、二、三均已打卡
- **When** 家长在数据看板查看连续完成明细，或孩子在我的统计中查看
- **Then** "练琴"显示连续 3 天
- **Given** 周三因孩子生病，"练琴"被家长取消
- **When** 结算后查看连续天数
- **Then** 取消不中断连续，"练琴"仍显示连续 3 天（周一、周二打卡，周三取消）
- **Given** 周四孩子忘记打卡，结算后连续中断
- **When** 查看连续天数
- **Then** "练琴"显示连续 0 天

#### US-CHK-08：查看整体连续天数（Should）

- **Given** 孩子"小明"有多个日常作息：练琴、阅读、起床
- **When** 周一完成练琴和阅读（2 项），周二仅完成起床（1 项），周三全部未完成
- **Then** 整体连续天数：周一 1 天 → 周二 2 天 → 周三中断归 0
- **Given** 某天全部日常作息日程均被取消
- **When** 结算时判定该天是否有有效日程
- **Then** 若所有日常作息均被取消，该天不计入"连续"判断（既不延续连续也不中断）。若至少有一个未被取消的日常作息，按正常规则判定

#### US-CHK-09：连续中断规则（Should）

- **Given** 孩子日常作息"阅读"，连续 5 天打卡
- **When** 第 6 天家长取消了"阅读"实例
- **Then** 连续天数保持 5 天，不中断（取消是家长主动操作）
- **Given** 第 7 天孩子未打卡，"阅读"逾期变为"未完成"
- **Then** 结算后连续天数归 0，连续中断
- **Given** 第 7 天尚未结束（当前时间在同一天内）
- **When** 前端展示连续天数
- **Then** 如果当天已打卡，则计入连续（如显示 6 天）；如果当天尚未打卡但时间窗口仍开放，则显示 5 天 + "今天还没打卡哦"提示，不中断连续

#### US-CHK-10：结算时更新连续天数（Should）

- **Given** 凌晨结算任务触发
- **When** 结算逻辑遍历每个孩子昨天的所有日常作息实例
- **Then** 对每个孩子：
  - 计算单一日程连续天数：若昨天某个日程已打卡 → 该日程连续 +1；若昨天某个日程未打卡（非取消）→ 该日程连续归 0
  - 计算整体连续天数：若昨天至少 1 个有效日常作息已完成 → 整体连续 +1；否则整体连续归 0
  - 更新数据库中的连续计数
- **Given** 结算过程中某条数据更新失败
- **When** 数据库写入异常
- **Then** 结算任务记录错误日志，重试失败的数据（最多 3 次）。不影响其他孩子的结算

### 10.3 完成率统计（Should）

#### US-CHK-11：按周查看完成率（Should）

- **Given** 孩子"小明"本周共有 10 个有效日程（排除已取消后），其中 8 个已完成打卡
- **When** 家长在数据看板选择"本周"
- **Then** 完成率显示 80%（8/10），附带与上周对比的升降箭头
- **Given** 本周所有日程均被取消（分母为 0）
- **When** 查看本周完成率
- **Then** 完成率显示"--"（不适用），提示"本周暂无有效日程"

#### US-CHK-12：按月查看完成率（Should）

- **Given** 孩子"小明"本月共有 40 个有效日程，其中 34 个已完成
- **When** 家长在数据看板选择"本月"
- **Then** 完成率显示 85%（34/40）
- **Given** 当前为月初（如 10 月 3 日），本月数据量极少
- **When** 查看本月完成率
- **Then** 正常显示当前累计完成率，不特殊处理。数据量少是正常状态

#### US-CHK-13：按类型拆分完成率（Should）

- **Given** 孩子"小明"本周课后活动 3/4 完成，日常作息 5/5 完成，作业任务 0/1 完成
- **When** 家长在看板中切换类型筛选为"课后活动"
- **Then** 完成率显示 75%（3/4）。趋势图切换为仅课后活动数据
- **Given** 选择"日常作息"
- **When** 查看
- **Then** 完成率显示 100%（5/5）
- **Given** 选择"作业任务"
- **When** 查看
- **Then** 完成率显示 0%（0/1）

#### US-CHK-14：按孩子独立计算（Should）

- **Given** 家庭中有两个孩子："小明"和"小红"，各有各自的日程
- **When** 家长查看小明的完成率
- **Then** 仅计算小明的日程实例，不混入小红的数据
- **Given** 家长在看板中切换到"小红"
- **When** 查看
- **Then** 完成率、连续天数等指标全部切换为小红的数据

### 10.4 家长端数据看板（Should）

#### US-CHK-15：看板页面基本布局（Should）

- **Given** 家长已登录，在日历视图
- **When** 点击顶部导航栏"看板"按钮或从日历视图侧滑进入
- **Then** 进入数据看板页面。显示：孩子切换栏（多孩子时）、时间范围切换（本周/本月）、核心指标卡片（完成率 + 连续天数）、完成率趋势图、连续完成明细列表
- **Given** 孩子切换栏、时间范围、核心指标均加载完成
- **When** 家长查看
- **Then** 各区域数据一致（同一孩子、同一时间范围）

#### US-CHK-16：多孩子切换展示（Should）

- **Given** 家庭有 2 个孩子"小明"和"小红"
- **When** 家长进入看板
- **Then** 顶部显示两个孩子 Tab，默认并列展示两个孩子的核心指标卡片。点击 Tab 可切换只看某一个孩子的完整看板
- **Given** 家庭只有 1 个孩子
- **When** 家长进入看板
- **Then** 不显示孩子切换栏，直接展示该孩子数据
- **Given** 家庭有 4 个孩子
- **When** 家长进入看板
- **Then** 默认切换模式，一次看一个孩子，不并列展示（避免卡片太挤）

### 10.7 结算机制（Must）

#### US-CHK-26：每日结算执行（Must）

- **Given** 每天凌晨（如 00:05），结算任务触发
- **When** 任务开始执行
- **Then** 遍历前一天所有未打卡的日程实例：
  - 课后活动：结束时间 + 2 小时后仍未打卡 → 状态变更为"已结束"
  - 日常作息：当天 24:00 仍未打卡 → 状态变更为"未完成"
  - 作业任务：截止日期当天 24:00 仍未打卡 → 状态变更为"逾期未完成"
- **After 结算完成后**：
  - 更新连续完成天数（单一日程连续 + 整体连续天数）
- **Given** 结算任务中途异常中断（如数据库连接失败）
- **When** 任务重试
- **Then** 结算任务具备幂等性——已结算的实例不可重复变更。使用状态字段判断（如"未完成"→"已结束"仅当当前状态为"未完成"时才变更；"未完成"终态不额外再变更）

## 11. 业务概念模型与状态映射

打卡与统计模块的核心业务实体及关系（概念层面，非数据库字段设计）：

- **打卡记录（Checkin）**：关联日程实例的完成状态（已完成/未完成），记录打卡人 ID、打卡时间、操作来源（家长端/孩子端）。一个日程实例最多一条打卡记录
- **连续完成（Streak）**：基于日常作息类型的连续打卡天数追踪。包含两个维度：单一日程连续（per-schedule）和整体连续天数（per-child global）
- **完成率（CompletionRate）**：已完成打卡数 /（总日程数 - 已取消数），按周/月粒度、按孩子、按类型拆分
- **成就徽章（Badge）**：基于单一日程连续天数的里程碑成就。孩子—徽章多对多关系，记录解锁时间
- **订阅记录（Subscription）**：用户微信订阅消息的授权状态，按模板类型记录
- **结算任务（Settlement）**：每天凌晨执行的定时任务，处理逾期判定、连续天数更新、徽章检测

### 11.1 视觉状态 ↔ 业务状态映射

`module-event.md` §10.2 定义 4 种视觉状态供前端渲染（未完成/已完成/已取消/已逾期），本文档 §2.4 使用 5 种业务状态供后端逻辑判定。映射关系如下：

| 视觉状态（UI） | 业务状态（后端） | 判定条件 |
|------|------|---------|
| 未完成 | 未完成（进行中） | 时间窗口开放，尚未打卡 |
| 已完成 | 已完成 | 已打卡 |
| 已取消 | 已取消 | 家长主动取消实例 |
| 已逾期 | 未完成（终态） | 日常作息：当天 24:00 结算后未打卡 |
| 已逾期 | 逾期未完成 | 作业任务：截止日期 24:00 结算后未打卡 |
| 已逾期 | 已结束 | 课后活动：结束时间 + 2 小时结算后未打卡 |

**设计要点**：前端统一以 4 种视觉状态渲染，"未完成（进行中）"和"未完成（终态）"在前端视觉层合并为"未完成"，仅在打卡按钮可用性上体现差异（终态不显示按钮）。

### 11.2 模块非功能要求

| 指标 | 目标 |
|------|------|
| 看板数据加载 | ≤ 2s（首屏），≤ 1s（切换孩子/时间范围） |
| 趋势图渲染 | ≤ 500ms（含数据聚合 + 图表绘制） |
| 结算任务执行 | ≤ 5 分钟（处理全量未打卡实例 + 连续更新） |
| 结算任务幂等性 | 已结算实例不可重复变更，多次执行结果一致 |
| 推送消息到达 | 微信限制：一次性订阅模板，每次推送消耗一次订阅次数 |
| 打卡时间判定 | 以服务器时间为准，客户端时间仅作展示参考 |
| 数据隔离 | 打卡记录、统计数据、看板数据按家庭隔离。多家庭用户在看板和统计中仅显示当前家庭的孩子的数据 |
