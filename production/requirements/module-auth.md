# 认证与账户模块 · 产品需求文档

> 版本：v1.0 | 日期：2026-08-04 | 状态：草案
>
> 所属产品：[家庭日程协作工具](index.md)
>
> 本文档为 `index.md` 的模块化拆分，聚焦认证与账户模块的详细设计。其他模块设计见对应模块文档。

## 1. 模块概述

认证与账户是用户进入系统的入口模块，负责微信授权登录、个人资料管理、"我的"页面、账户注销等账户全生命周期。认证完成后交接给家庭模块，由家庭模块承接首次引导和家庭管理。

**核心能力：**

- 微信静默登录（`wx.login` → openid / session_key）
- 昵称头像收集（单页面，可跳过，使用微信原生控件）
- 登录态管理（JWT + 本地存储 + 静默续期）
- 用户资料查看与编辑
- "我的"页面（个人资料 + 家庭操作入口）
- 账户注销（30 天缓冲后永久删除）

**与其他模块的关系：**

- 家庭模块：认证完成后，由家庭模块检查用户家庭状态，无家庭时展示引导页
- 日程管理：JWT 携带用户身份，所有 API 请求需携带 JWT，后端按家庭隔离数据
- "我的"页面：属于认证模块，提供家庭切换 / 创建 / 加入入口，具体流程由家庭模块承接

## 2. 认证方式设计

### 2.1 认证链路

首期采用**微信静默登录**，不收集手机号。手机号收集待小程序完成企业主体认证后补充。

```
wx.login → code → 后端 → 微信 API → openid + session_key
                              ↓
                         查找/创建账户
                              ↓
                         签发 JWT → 返回前端 → 存储至 Storage
```

### 2.2 各环节说明

| 环节 | 方式 | 用户体验 | 说明 |
|------|------|---------|------|
| 获取 code | `wx.login()` | **无感知** | 小程序端调用，获取一次性 code |
| 换取 openid | 后端 `jscode2session` | 无感知 | 后端用 code + appid + secret 向微信服务端换取 |
| 账户匹配 | openid 索引 | 无感知 | 已有用户返回已有账户，新用户自动创建账户 |
| 签发 token | 后端生成 JWT | 无感知 | JWT 含 userId、签发时间、过期时间 |
| 存储 token | `wx.setStorageSync` | 无感知 | 前端持久化，后续所有请求携带 |

### 2.3 昵称头像收集

昵称和头像通过独立的过渡页面收集，**可跳过**。跳过时使用默认值。

| 字段 | 获取方式 | 说明 |
|------|---------|------|
| 昵称 | `<input type="nickname">` | 微信原生控件，点击后弹出微信昵称列表，用户一键确认即可 |
| 头像 | `<button open-type="chooseAvatar">` | 微信原生控件，点击后弹出微信头像选择器 |

**默认值策略：**

| 字段 | 跳过时默认值 |
|------|------------|
| 昵称 | "微信用户" |
| 头像 | 灰色默认头像占位图 |

**修改入口**："我的"页面点击头像区域 → 进入编辑页，可随时修改。

### 2.4 首期不做的事

| 事项 | 原因 | 后续计划 |
|------|------|---------|
| 手机号收集 | 小程序非企业主体，无法调用 `getPhoneNumber` | 企业认证后补充 |
| 手动输入手机号 + 短信验证 | 首期不引入短信服务成本 | 按需评估 |

### 3.5 边界与异常

| 场景 | 处理 |
|------|------|
| `wx.login` 调用失败（微信服务异常） | 提示"登录失败，请检查网络后重试"，提供"重试"按钮 |
| code 换 openid 超时（后端/微信 API 异常） | 提示"服务繁忙，请稍后重试"，自动重试 1 次 |
| 用户清除微信 Storage（Token 丢失） | 下次打开时重新走完整登录流程，用户无感知 |
| 微信账号切换（同一设备） | `wx.login` 返回新 openid → 后端创建/匹配新账户 |
| 首次登录时网络异常 | 昵称头像收集页不依赖网络，可正常操作；提交时若网络异常则本地暂存、网络恢复后补传 |
| 用户跳过昵称头像后又立即去"我的"页面修改 | 正常流程，编辑页与收集页为同一组件 |

## 4. 登录态管理

### 4.1 Token 策略

| 项目 | 方案 |
|------|------|
| Token 类型 | JWT（自签发） |
| 载荷 | userId、openid、签发时间（iat）、过期时间（exp） |
| 有效期 | **7 天** |
| 存储位置 | `wx.setStorageSync('token', jwt)` |
| 传输方式 | HTTP Header `Authorization: Bearer <jwt>` |

### 4.2 请求链路

```
前端每次请求
  → 请求拦截器：从 Storage 读取 JWT，写入 Authorization Header
  → 发起请求
  → 响应拦截器检查状态码
    ├─ 200 → 正常返回
    └─ 401 → 自动续期流程：
              1. wx.login() 获取新 code
              2. 后端用 code 换取 openid → 签发新 JWT
              3. 前端存储新 JWT
              4. 重放原请求
              （用户全程无感知）
```

### 4.3 续期失败处理

| 场景 | 处理 |
|------|------|
| 续期成功 | 静默完成，用户无感知 |
| 续期时网络异常 | 提示"网络异常，请检查网络"，提供"重试"按钮 |
| 续期时微信 `wx.login` 失败 | 提示"登录已过期，请重新打开小程序"，清除 token |
| 续期时后端返回非 200（非网络原因） | 同上，提示重新打开 |

### 4.4 登录态状态机

```
    ┌──────────┐     登录成功       ┌──────────┐
    │  未登录   │ ──────────────→  │  已登录    │
    └──────────┘                   └──────────┘
        ↑                              │
        │       Token 过期 7 天         │
        │         或手动退出            │
        └──────────────────────────────┘
```

**说明**：首期不设"退出登录"功能（用户可能退出后不知如何重新登录）。如需退出，用户通过微信的"删除小程序"来清除数据。

### 4.5 多设备登录

**不限制多设备同时登录**。同一微信账号在不同手机上登录，各自持有独立的 JWT，互不影响。理由是家庭日程工具属于协作场景，不存在金融级安全风险，限制单设备登录会带来不必要的用户体验问题。

### 4.6 边界与异常

| 场景 | 处理 |
|------|------|
| Token 即将过期但在使用中 | 请求返回 401 时自动续期，不提前刷新 |
| 多个请求同时返回 401 | 请求拦截器对续期操作加锁，只执行一次 `wx.login`，其余请求等待续期完成后重放 |
| Token 被篡改 | 后端验签失败返回 401，前端走续期流程（静默重新登录） |
| Storage 满无法写入 Token | `wx.setStorageSync` 失败时提示"存储空间不足，请清理微信缓存" |

## 5. 用户资料

### 5.1 资料模型

| 字段 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| 用户 ID | 系统生成 | 是 | 后端自动生成，不可修改 |
| openid | 字符串 | 是 | 微信小程序 openid，后端存储，不可修改 |
| 昵称 | 字符串 | 是 | 全局唯一，默认"微信用户" |
| 头像 | URL | 是 | 全局唯一，默认灰色占位图 |
| 创建时间 | 时间戳 | 是 | 首次 `wx.login` 时自动记录 |
| 最后登录时间 | 时间戳 | 是 | 每次登录自动更新 |

**设计要点：**

- **只有账户级资料，没有家庭级资料。**所有家庭共用同一份昵称和头像
- 昵称和头像为全局设置，在任一家庭中修改后，其他家庭看到的也是新值
- 家庭模块中"孩子姓名"仅作为邀请时的标签存储，不替代昵称显示（详见 [module-family.md](module-family.md)）
- **家庭内显示规则**：孩子姓名在家庭内所有场景（成员列表、日程卡片、打卡记录、数据看板）覆盖微信昵称，详见 [module-family.md §4.5](module-family.md#45-孩子姓名显示规则)

### 5.2 资料编辑

```
"我的"页面 → 点击头像区域 → 进入编辑页

┌──────────────────────────────────────┐
│  ← 编辑资料                          │
│                                      │
│          （当前头像）                  │
│           [更换头像]                  │
│                                      │
│  昵称  ┌──────────────────────────┐  │
│        │ 当前昵称                   │  │
│        └──────────────────────────┘  │
│                                      │
│              [保存]                   │
│                                      │
└──────────────────────────────────────┘
```

| 要点 | 说明 |
|------|------|
| 头像修改 | 使用 `<button open-type="chooseAvatar">`，选择后立即上传、保存 |
| 昵称修改 | 使用 `<input type="nickname">`，支持清空重新输入 |
| 保存 | 调后端接口更新，成功后返回"我的"页面并刷新显示 |
| 频率限制 | 无限制 |

### 5.3 边界与异常

| 场景 | 处理 |
|------|------|
| 保存时网络异常 | 提示"保存失败，请检查网络"，保留用户输入内容 |
| 头像上传失败 | 提示"头像上传失败，请重试"，不保存昵称修改（事务一致性） |
| 昵称为空 | 不允许保存，提示"昵称不能为空" |
| 昵称过长（>20 字符） | 限制输入长度，前端截断 + 后端校验 |
| 昵称含敏感词 | 后端校验，拒绝保存并提示"昵称包含不允许的词汇" |

## 7. 账户注销

### 7.1 注销条件

用户在注销前 MUST 先退出所有家庭。

| 场景 | 处理 |
|------|------|
| 用户属于 1 个家庭 | 提示"请先退出家庭后再注销"，跳转家庭管理页 |
| 用户属于多个家庭 | 提示"请先退出所有家庭后再注销"，列出用户所属家庭 |
| 用户是某家庭的创建者且还有成员 | 需先解散或转让家庭（见 module-family.md） |
| 用户不属于任何家庭 | 满足注销条件，进入注销流程 |

### 7.2 注销流程

```
"我的" → "设置" → "注销账户"

  ┌──────────────────────────────────────┐
  │  注销账户                            │
  │                                      │
  │  ⚠ 注销后：                          │
  │  · 你的个人资料（昵称、头像、openid） │
  │    将在 30 天后永久删除               │
  │  · 30 天内重新登录可恢复账户           │
  │  · 你在各家庭的打卡记录将匿名化保留    │
  │                                      │
  │  确认注销请点击下方按钮               │
  │                                      │
  │         [取消]      [确认注销]        │
  └──────────────────────────────────────┘
        ↓ 确认
  ┌──────────────────────────────────────┐
  │  二次确认                            │
  │  确定要注销账户吗？此操作不可撤销。    │
  │                                      │
  │         [再想想]    [确定注销]        │
  └──────────────────────────────────────┘
        ↓ 确定
  后端标记账户为"已注销"状态 → 清除本地 token → 关闭小程序
```

### 7.3 注销后数据保留

| 数据 | 处理 | 说明 |
|------|------|------|
| 个人资料（昵称、头像、openid） | 保留 30 天，到期永久删除 | 30 天内重新登录可恢复 |
| 打卡记录 | 匿名化保留 | 移除用户关联，保留"某人在某日完成某事"的事实记录 |
| 家庭成员关系 | 标记"已注销" | 成员列表中显示为"已注销成员" |
| Token | 立即失效 | 30 天内重新登录发放新 Token |

### 7.4 恢复注销

注销后 30 天内，用户重新打开小程序：

```
打开小程序 → wx.login → 后端发现"已注销"状态且未到期
  → 提示页面：
  ┌──────────────────────────────────────┐
  │  你的账户已申请注销                   │
  │                                      │
  │  数据保留至 2026 年 9 月 3 日         │
  │  （剩余 23 天）                       │
  │                                      │
  │  [恢复账户]      [知道了]             │
  └──────────────────────────────────────┘
```

- "恢复账户"：立即恢复，JWT 签发，进入正常使用
- "知道了"：关闭小程序，保持已注销状态

### 7.5 边界与异常

| 场景 | 处理 |
|------|------|
| 30 天到期后重新登录 | 视为新用户，自动创建新账户 |
| 注销时网络异常 | 保持原状态，提示"操作失败，请重试" |
| 用户注销后，家庭还在 30 天解散缓冲期内 | 各自独立倒计时，账户恢复不影响家庭解散倒计时 |
| 注销后用户在其他家庭中的打卡记录 | 匿名化保留，不因用户注销而丢失 |

## 附录 B：与微信小程序的合规性

### B.1 隐私政策

微信审核要求小程序在收集用户信息前明确告知并获得同意。本模块设计中：

- 首次打开弹出隐私政策弹窗，用户勾选同意后方可调用 `wx.login`
- 用户拒绝时仅展示静态提示页，不调用任何 API，不收集任何信息

### B.2 账户注销

微信审核要求小程序提供用户注销功能。本模块设计中：

- "设置" → "注销账户"，二次确认后执行
- 注销前须退出所有家庭
- 30 天缓冲期内可恢复

### B.3 昵称头像

使用微信原生控件（`<input type="nickname">` + `<button open-type="chooseAvatar">`），符合微信新版规范中"不默认获取用户信息"的要求。
