## 1. 产品概述

### 1.1 变更背景

现有日程管理模块的日程对象仅限「孩子」——创建流程第一步为「选孩子」，字段「关联孩子」必填、可多选（[module-event.md §4.1](../../requirements/module-event.md#4-创建流程)）。家长自身及家庭中其他家长的日程无法进入系统，日历里只有孩子的安排。

### 1.2 变更目标

将日程关联对象从「孩子」泛化为「家庭成员」（家长 + 孩子），使家长可以为自己、其他家长、孩子创建日程，实现"全家人的日程都在一个日历里"。

### 1.3 范围边界

- **做**：关联对象泛化、类型双文案、打卡泛化到成员、模板关联成员泛化
- **不做**：家长日程统计（统计仍孩子维度）、家长独立类型体系/自定义类型、展示模式改动、存量数据迁移

## 2. 用户角色与权限变更

> 角色定义与账户模型见 [index.md §2](../../requirements/index.md#2-用户角色)，原权限矩阵见 [index.md §2.3](../../requirements/index.md#23-权限矩阵)。本节只写变更。

| 能力 | 家长 | 孩子 |
|------|------|------|
| 创建日程 | 可给任意成员创建（自己 / 其他家长 / 孩子） | 仅给自己创建（高年级自主添加） |
| 编辑/删除日程 | 任意成员的日程 | 仅自己的日程（高年级） |
| 分配日程对象 | 家庭成员（家长 + 孩子） | 仅自己 |
| 打卡确认 | 给自己 + 代任意成员 | 仅自己 |
| 查看日程 | 全家庭成员 | 仅自己 |

**关键权限约束**：

- 孩子（高年级自主添加）创建日程时，关联对象**默认自己且不可更改**，不可选家长。既有规则"仅关联自己、不支持多选"（[module-display-mode.md §5.3.2](../../requirements/module-display-mode.md#53-自主添加日程)）本次明确扩展为"不可关联家长"。
- 孩子不能给家长创建日程，亦不能编辑/删除/代打卡家长的日程。
- 家长之间可互相创建/编辑/删除日程（沿用"家长可管理所有日程"的既有协作语义）。

## 3. 功能模块变更

### 3.1 日程管理模块

| 变更点 | 原 | 新 |
|--------|----|----|
| 创建流程第一步 | 选孩子 | 选成员（家长视角 = 全体成员多选；孩子高年级视角 = 仅自己） |
| 详情页关联区 | 关联孩子 | 关联成员 |
| 日历筛选 | 按孩子 | 按成员 |
| 日历卡片标签 | 孩子头像/名 | 成员头像/名 |
| 孩子端可见性 | 仅显示自己的日程 | 不变（家长日程对孩子不可见） |

### 3.2 打卡模块

打卡对象从「孩子」泛化为「成员」。家长可给关联自己的日程打卡，也可为其他成员代打卡——沿用 [module-event.md §8.3](../../requirements/module-event.md#83-家长端-vs-孩子端) 家长"可帮孩子打卡"既有语义，扩展对象到家长。打卡时间窗口、逾期判定、结算规则不变（[module-checkin.md](../../requirements/module-checkin.md)）。

### 3.3 模板模块

模板使用时的「关联孩子」（[module-template.md §5](../../requirements/module-template.md#5-一键创建日程)）泛化为「关联成员」，模板可生成家长日程。

### 3.4 统计模块（不涉及）

统计仍以「家庭 + 孩子」为维度（[module-checkin.md](../../requirements/module-checkin.md)）。家长日程不进入完成率、连续天数、数据看板、孩子"我的统计"。

### 3.5 展示模式模块（不涉及）

展示模式是孩子端专属渲染开关（[module-display-mode.md](../../requirements/module-display-mode.md)），本次变更不触碰。

## 4. 日程类型双文案

三种类型枚举不变，仅「作业任务」在家长视角下改文案：

| 类型 | 家长端文案 | 孩子端文案 |
|------|-----------|-----------|
| 课后活动 | 课后活动 | 课后活动 |
| 日常作息 | 日常作息 | 日常作息 |
| 作业任务（枚举不变） | 待办事项 | 作业任务 |

**切换规则**：按当前登录用户角色切换前端文案，后端枚举值与数据不变。家长登录（含创建/查看任意日程）显示「待办事项」；孩子登录显示「作业任务」。

> 语义：家长给自己/其他家长创建的该类型日程本质是"待办事项"（如"记得交物业费""周五前报税"）；给孩子创建的是"作业任务"。同一类型、两套文案，避免为家长引入独立类型体系。

## 5. 展示模式

不涉及（见 §3.5）。家长无展示模式概念，孩子展示模式渲染逻辑不变。

## 6. 页面结构变更

| 页面 | 变更点 |
|------|--------|
| 创建日程页 | 第一步「选成员」：家长视角展示全体家庭成员（家长 + 孩子）多选；孩子高年级视角默认自己、不可改 |
| 日程详情页 | 「关联孩子」区改「关联成员」区，显示成员名（家长名/孩子名） |
| 日历视图 | 筛选栏「按孩子」→「按成员」；卡片头像/名显示成员；默认"全部成员" |
| 数据看板 | 不变（仍按孩子，家长日程不进入） |

> 孩子端日历仅显示关联自己的日程；家长日程即使关联某家长，也不会出现在任何孩子端视图中。

## 7. 业务概念模型

概念层面（非数据库设计）：日程（Schedule）的关联对象从「孩子」扩展为「家庭成员」（家长或孩子）。家庭成员（FamilyMember）是日程的关联单元，家长与孩子均为其子集。

- 打卡记录（Checkin）：打卡人可为任意家庭成员，打卡对象为关联该成员的日程实例
- 统计（CompletionRate/Streak）：仍以「孩子」为计算维度，家长日程不参与

> 数据库字段/表结构/迁移方案属技术设计阶段（arch-architect）产出，本文档不做字段设计。

## 10. GWT 用户故事与验收标准

> 编号 US-PAR（parent schedule）。优先级标注于标题末尾，未标注者默认 Must。

### 10.1 创建（关联对象泛化）

#### US-PAR-01：家长给自己创建日程 [Must]

- **Given** 家长已登录，在创建流程「选成员」步骤
- **When** 选择自己 → 选择类型 → 填写字段 → 点击"创建"
- **Then** 系统生成日程，关联对象为该家长本人，在家长端日历展示；返回日历视图可见。
- **Given** 家长在「选成员」步骤未选择任何成员
- **When** 点击"下一步"
- **Then** 系统提示"请至少选择一个成员"，不进入下一步

#### US-PAR-02：家长给其他家长创建日程 [Must]

- **Given** 家长 A 已登录，家庭中还有家长 B
- **When** 在「选成员」步骤选择家长 B → 填写并创建
- **Then** 日程关联家长 B。家长 A 与家长 B 的日历均可见该日程；孩子端不可见。

#### US-PAR-03：家长混合给成员创建日程（家长 + 孩子）[Must]

- **Given** 家长已登录，家庭中有孩子"小明"和家长 B
- **When** 在「选成员」步骤同时选择家长 B 与小明 → 创建
- **Then** 日程同时关联家长 B 与小明。家长端日历可见，打卡记录各自独立（家长 B 和小明各有一条打卡记录）。

#### US-PAR-04：家长给孩子创建日程（回归，既有能力不退化）[Must]

- **Given** 家长已登录
- **When** 按原流程为孩子创建课后活动/日常作息/作业任务
- **Then** 与 [module-event.md §13.1](../../requirements/module-event.md#131-日程创建) US-EVT-01~03 行为完全一致，不因泛化而退化。

#### US-PAR-05：孩子（高年级）给自己创建日程，不能选家长 [Must]

- **Given** 高年级模式的孩子进入创建日程页
- **When** 查看「选成员」步骤
- **Then** 关联对象默认自己且不可更改，不可多选，列表中不出现家长。
- **Given** 孩子（非高年级）尝试进入创建流程
- **When** 访问创建入口
- **Then** 不提供创建入口（沿用 [module-display-mode.md §2.1](../../requirements/module-display-mode.md#21-模式对比总览) 自主添加仅高年级模式）。

#### US-PAR-06：孩子不能给家长创建日程（越权拦截）[Must]

- **Given** 孩子（高年级）在创建日程时，通过篡改请求/接口参数将关联对象指向某家长
- **When** 提交创建请求
- **Then** 服务端拒绝（返回 403 + 权限错误），不创建日程。
- **Given** 孩子尝试编辑/删除某家长的日程
- **When** 提交操作
- **Then** 服务端拒绝（403），日程不变。

### 10.2 类型双文案

#### US-PAR-07：家长视角显示「待办事项」[Must]

- **Given** 家长登录
- **When** 查看"作业任务"类型（创建页类型卡片、详情页类型标签、日历筛选）
- **Then** 均显示为「待办事项」。

#### US-PAR-08：孩子视角显示「作业任务」[Must]

- **Given** 孩子登录
- **When** 查看"作业任务"类型相关界面
- **Then** 均显示为「作业任务」。

### 10.3 打卡（泛化到成员）

#### US-PAR-09：家长给自己日程打卡 [Must]

- **Given** 家长有自己的日程（如"健身课"），状态"未完成"且未逾期
- **When** 点击打卡
- **Then** 状态变"已完成"，后台记录打卡人 = 该家长本人。

#### US-PAR-10：家长代其他家长/孩子打卡 [Must]

- **Given** 家长 A 查看关联家长 B 或孩子"小明"的未完成日程
- **When** 点击打卡
- **Then** 状态变"已完成"，后台记录打卡人 = 家长 A，被打卡对象 = 家长 B / 小明。

### 10.4 统计隔离

#### US-PAR-11：家长日程不进入统计 [Must]

- **Given** 家庭中家长 A 有 1 个自己的日程，孩子"小明"有若干日程
- **When** 家长查看数据看板 / 小明查看"我的统计"
- **Then** 家长 A 的日程不计入任何完成率、连续天数、趋势、看板指标；看板仅统计孩子的日程。

### 10.5 孩子端可见性

#### US-PAR-12：孩子端不显示家长日程 [Must]

- **Given** 家庭中家长 A 有一个仅关联自己的日程
- **When** 孩子"小明"查看日历（今日/周/月视图）
- **Then** 该家长日程不出现。小明仅能看到关联到自己的日程。

### 10.6 日历筛选

#### US-PAR-13：日历按成员筛选 [Must]

- **Given** 家长在日历视图
- **When** 在筛选栏选择某家长（如"爸爸"）
- **Then** 日历仅显示关联该家长的日程；筛选条件跨月/周/日视图保持。
- **Given** 筛选栏默认态
- **When** 查看
- **Then** 默认"全部成员"（家长 + 孩子）。

### 10.7 模板

#### US-PAR-14：模板生成家长日程 [Should]

- **Given** 家长在模板管理页选择某模板
- **When** 在使用面板的"关联成员"选择器选择某家长（或自己）→ 指定起始日期 → 创建
- **Then** 系统生成关联该家长的日程。
- **Given** 所选模板关联成员与当前家庭不匹配
- **When** 使用模板
- **Then** 系统自动清理成员关联，要求重新指定（沿用 [module-event.md US-EVT-04](../../requirements/module-event.md#131-日程创建) 既有行为）。

## 11. 边界与异常覆盖

| # | 场景 | 预期行为 |
|---|------|---------|
| BE-01 | 孩子给家长创建（越权） | 前端不展示家长为可选对象；后端拦截返回 403，不落库 |
| BE-02 | 孩子编辑/删除/代打卡家长日程（越权） | 后端拦截返回 403，日程不变 |
| BE-03 | 家长日程进入统计 | 统计查询仅按孩子维度过滤，家长日程被排除，不污染完成率/看板 |
| BE-04 | 类型文案切换 | 按登录角色渲染；后端枚举值不变，跨端数据一致 |
| BE-05 | 关联成员（家长或孩子）被移出家庭 | 沿用 [module-event.md BE-18/BE-23](../../requirements/module-event.md#14-边界与异常覆盖)：编辑提交时校验成员仍在家庭，已移除成员打卡条目标记"已离群"，不接收新打卡 |
| BE-06 | 混合关联（家长 + 孩子）打卡 | 各成员打卡记录独立，一方打卡不影响另一方（沿用多孩子打卡独立语义） |
| BE-07 | 家庭无孩子、仅家长 | 创建日程不再阻塞（原 BE-08"无孩子"空态不再适用）；家长可给自己/其他家长创建 |
| BE-08 | 孩子端误触家长日程 | 孩子端数据按"仅关联自己"过滤，家长日程天然不可见 |
| BE-09 | 并发编辑家长日程 | 沿用 [module-event.md BE-16](../../requirements/module-event.md#14-边界与异常覆盖) 乐观锁冲突提示 |
| BE-10 | 日历筛选"按成员"无匹配 | 显示空状态"该筛选条件下无日程" |
