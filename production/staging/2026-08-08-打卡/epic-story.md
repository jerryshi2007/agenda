## Story: CHK-ST-01 打卡时间窗口 + 每日结算

| 字段 | 值 |
|------|-----|
| 本地 ID | CHK-ST-01 |
| 标题 | 打卡与统计模块首期：打卡时间窗口规则 + 每日结算任务 |
| 模块名 | module-checkin |
| 描述 | 实现打卡时间窗口的完整规则：提前 30 分钟打卡窗口、三种日程类型（课后活动/日常作息/作业任务）的差异化逾期判定、逾期后不可补打卡、以服务器时间为准的时间判定。实现每日凌晨结算定时任务：根据时间窗口规则自动变更未打卡日程状态（已结束/未完成/逾期未完成），变更时保证幂等性。首期打卡交互（按钮、状态切换、打卡/撤销）已在日程管理模块完成，本 Story 仅关注时间边界规则和结算逻辑。 |
| 覆盖用户故事 | US-CHK-01, US-CHK-02, US-CHK-03, US-CHK-04, US-CHK-05, US-CHK-06, US-CHK-26 |
| 覆盖边界异常 | BE-05（多端同时打卡）、BE-06（跨天打卡服务器时间为准）、BE-07（提醒设置边界）、BE-08（取消恢复后打卡）、BE-09（取消恢复不回溯统计）、BE-10（编辑时间不影响历史）、BE-11（删除日程记录保留）、BE-15（结算任务重试）、BE-18（结算中打卡不受影响） |
| 优先级 | Must（第一期） |
| 预估工时 | 3 个工作日 |
| 依赖 | 日程管理模块（EVT-ST-03 日程详情页与全操作）——打卡按钮交互和状态定义已在日程模块完成 |
| 飞书链接 | 待回填 |
| 状态 | confirmed |

**关键后端逻辑：**

1. **打卡时间窗口判定**（API 层）：
   - 输入：日程 ID、日程类型、开始时间、结束时间（或截止日期）、服务器当前时间
   - 提前打卡窗口：`canCheckin = serverTime >= startTime - 30min`
   - 课后活动逾期：`isOverdue = serverTime > endTime + 2h AND notCheckedIn`
   - 日常作息逾期：结算时判定（当天 24:00 后）
   - 作业任务逾期：结算时判定（截止日期 24:00 后）
   - 终态日程：所有打卡请求返回"打卡窗口已关闭"

2. **每日结算任务**（定时任务/云函数触发器）：
   - 触发时间：每天 00:05
   - 遍历前一天的未打卡日程实例
   - 按类型变更状态：课后活动 → "已结束"，日常作息 → "未完成"，作业任务 → "逾期未完成"
   - 幂等性保障：仅当当前状态为"未完成"时才变更为终态，已终态的跳过
   - 异常处理：单条失败不影响其他，最多重试 3 次

**关键前端逻辑：**

- 日程详情页打卡按钮根据时间窗口动态变化状态（可点击 / 灰色不可点击 + 倒计时 / 不显示按钮）
- 以服务器返回时间为准展示，客户端时间仅做乐观 UI 参考
- 打卡请求前前端做一次客户端时间校验（提前窗口），减少无效请求

**关键数据结构（概念层）：**

- 打卡记录实体：关联日程实例 ID、打卡人 ID、打卡时间（服务器时间）、操作来源（家长端/孩子端）
- 日程实例状态：未完成 / 已完成 / 已结束 / 逾期未完成 / 已取消
- 结算任务需感知的日程字段：日程类型、开始时间、结束时间、截止日期、当前状态
