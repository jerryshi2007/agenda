# 孩子展示模式模块 · 需求文档

<!-- STAGING-STATUS: in-progress -->

## 1. 产品概述

详见 [孩子展示模式模块](../../../production/requirements/module-display-mode.md) 第 1 节。

**核心定位**：孩子端界面根据展示模式呈现不同的视觉和交互体验，适配不同年龄孩子的认知水平。三种模式共享同一份日程数据，仅视图层差异。

**核心价值**：
- 学龄前（3-6岁）：大卡片 + 红绿灯 + 弹窗确认，降低认知负担
- 小学（6-10岁）：基准只读视图，接近家长端但简化
- 高年级（10-14岁）：支持孩子自主添加日程，培养自我管理能力

## 2. 用户角色

详见 [产品需求总纲](../../../production/requirements/index.md#2-用户角色) 和 [家庭管理模块](../../../production/requirements/module-family.md#3-角色与权限)。

| 角色 | 权限 |
|------|------|
| 家长 | 可为每个孩子设置展示模式，可随时更改，可预览孩子端效果 |
| 孩子（学龄前）| 仅查看今日日程，按时段分组，点击卡片弹窗打卡 |
| 孩子（小学）| 查看今日/周/月日程，点击打卡按钮直接打卡，查看本周完成率 |
| 孩子（高年级）| 在小学模式基础上，可自主添加日程，查看丰富个人统计 |

| **学龄前模式** | | |

| 今日/周/月只读视图 | Must | 基准视图，一期全量开发 |
| 直接点击打卡 + 撤销 | Must | 一期全量开发 |
| 我的页面显示本周完成率 | Must | 一期全量开发 |
| **高年级模式** | | |

- **Must**：必须实现，不做则模块核心能力不完整
- **Should**：应该实现，缺失会影响用户体验但不影响核心流程
- **Could**：可选，可以后续迭代

### 模式对比速览

| 维度 | 学龄前（3-6 岁） | 小学（6-10 岁） | 高年级（10-14 岁） |
|------|:--:|:--:|:--:|
| 可用视图 | 仅今日 | 今日 + 周 + 月 | 今日 + 周 + 月 |
| 时间显示 | 时段标签 | 具体时间 | 具体时间 |
| 卡片样式 | 大色块 + 卡通图标 | 文字 + 图标 + 时间 | 接近成人视图 |
| 打卡方式 | 点击卡片 → 弹窗确认 | 点击按钮直接确认 | 点击按钮直接确认 |
| 状态指示 | 红绿灯颜色 | 标准 ✓/✗ 图标 | 标准 ✓/✗ 图标 |
| 自主添加日程 | ✗ | ✗ | ✓ |
| 查看统计 | ✗ | 本周完成率 | 完成率 + 连续天数 + 按类型 |

## 5. 页面结构

详见 [module-display-mode.md](../../../production/requirements/module-display-mode.md)：

- **学龄前模式**：仅今日视图一页
- **小学模式**：今日 + 周 + 月 + 我的（4 页）
- **高年级模式**：今日 + 周 + 月 + 我的（4 页，今日视图增加"+"添加按钮）

## 6. 业务概念模型

**展示模式**是孩子端 UI 的"渲染开关"：

- 展示模式作为孩子成员的属性存储在家庭数据中
- JWT 携带当前用户（孩子）的展示模式标识
- 孩子端进入页面时，根据模式标识选择对应的渲染逻辑
- 三种模式共享同一份日程数据，仅改变展示方式，不改变数据本身
- 模式切换对历史数据无影响，切换后数据连续不断层

## 7. 非功能需求

| 维度 | 要求 |
|------|------|
| 性能 | 模式切换后页面加载 ≤ 500ms；卡片点击响应 ≤ 100ms |
| 兼容性 | 微信小程序基础库 ≥ 2.10.0；iOS 12+ / Android 8.0+ |
| 安全性 | 孩子端仅可查看/打卡/（高年级）添加自己的日程，不可编辑他人日程 |
| 可用性 | 学龄前模式可点击区域 ≥ 88rpx × 88rpx，适配幼儿点击 |

## 8. 分期规划

详见 [module-display-mode.md §7](../../../production/requirements/module-display-mode.md#7-首期与二期范围)。

| 阶段 | 功能范围 |
|------|----------|
| **一期（当前开发）** | 小学模式（统一基准视图）全量上线，包含今日/周/月只读视图 + 直接打卡 + 本周完成率。一期无多模式切换，默认固定使用小学模式。 |
| **二期** | 家长端模式配置入口 + 学龄前模式差异化 UI + 高年级模式差异化 UI + 高年级自主添加日程 + 高年级个人统计 |

## 9. 验收标准（Given-When-Then）

### 小学模式（Must）

#### 场景 1：孩子打开今日视图
```
Given 孩子账户使用小学模式
When 孩子进入今日视图
Then 按时间线展示所有今日日程
And 每项显示类型图标 + 名称 + 具体时间 + 状态图标
And 顶部显示今日进度"已完成 X/Y"
And 所有日程不可编辑
```

#### 场景 2：孩子打卡
```
Given 孩子账户使用小学模式，日程处于待完成状态
When 孩子点击打卡按钮
Then 打卡立即确认，无需弹窗
And 状态图标更新为 ✓
And 今日进度 X/Y 更新
```

#### 场景 3：孩子撤销打卡
```
Given 孩子账户使用小学模式，日程已打卡完成
When 孩子点击已打卡的日程
Then 打卡撤销
And 状态图标恢复为待完成
And 今日进度更新
```

#### 场景 4：空态展示
```
Given 孩子今日无日程
When 孩子进入今日视图
Then 显示空态提示"今天还没有日程"
```

### 模式切换（Must）

#### 场景 5：家长更改展示模式后孩子端生效
```
Given 孩子当前使用小学模式，家长在家庭设置中将其改为学龄前模式
When 孩子正在使用小程序，切换到周视图
Then 页面以学龄前模式渲染（仅今日视图可用）
```

#### 场景 6：未设置模式时默认
```
Given 新增孩子，家长未设置展示模式
When 孩子首次进入小程序
Then 默认使用小学模式渲染
```

### 高年级模式（Should，二期）

#### 场景 7：孩子自主添加日程
```
Given 孩子账户使用高年级模式
When 孩子点击今日视图的"+"按钮
Then 进入创建日程页面
And 默认关联自己，不可更改关联孩子
And 创建完成后，日程在今日视图显示并带✏️标记
And 家长端可看到该日程并带✏️标记
```

#### 场景 8：从高年级切换到小学模式后孩子端视图
```
Given 孩子使用高年级模式，孩子已自主添加了 3 条日程
When 家长切换到小学模式，孩子重新进入小程序
Then 孩子端仅显示家长添加的日程，不显示孩子自主添加的日程
And 家长端仍可看到和编辑所有日程（含孩子添加的）
```

### 边界异常（Must）

#### 场景 9：网络异常加载失败
```
Given 孩子端网络断开
When 孩子进入今日视图
Then 显示网络连接失败的提示
And 提示样式匹配当前模式（学龄前显示卡通提示，小学/高年级显示标准提示）
```
