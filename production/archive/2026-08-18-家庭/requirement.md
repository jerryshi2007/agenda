# 家庭管理模块 · 需求文档

**原始文档：** [../../../requirements/module-family.md](../../../requirements/module-family.md)

本文档基于原始文档进行结构化补充，补充 GWT 验收标准、优先级分级、待讨论项处置结论。

## 1. 产品概述

详见 [../../../requirements/module-family.md#1-模块概述](../../../requirements/module-family.md#1-模块概述)

**核心价值：** 家庭是日程数据隔离边界，所有日程和打卡数据按家庭分组。家庭管理模块负责家庭生命周期全流程管理，支持多家长协作和多孩子不同展示模式设置。

## 2. 用户角色

详见 [../../../requirements/index.md#2-用户角色](../../../requirements/index.md#2-用户角色) 及 [../../../requirements/module-family.md#4-成员列表与角色管理](../../../requirements/module-family.md#4-成员列表与角色管理)

### 3.2 Given-When-Then 验收标准

#### F1 家庭创建

**场景 1：首次登录无家庭，创建家庭**
```gherkin
Given 用户已登录且无任何家庭
When 用户在引导页点击"创建家庭"，输入家庭名称"我们家"，选择角色"家长"，点击创建
Then 家庭创建成功
And 用户成为该家庭第一个成员，角色为家长
And 跳转到日历视图（空态），提示"快去邀请成员吧"
```

**场景 2：创建者选择孩子角色**
```gherkin
Given 用户已登录且无任何家庭
When 用户创建家庭，输入名称，选择角色"孩子"，点击创建
Then 家庭创建成功
And 用户成为该家庭第一个成员，角色为孩子
And 成员列表顶部提示"暂无家长，建议邀请家长管理"
And 展示模式默认为小学模式
And 用户可在成员列表点击自己，将角色修改为家长
```

**场景 3：已有家庭，修改名称**
```gherkin
Given 用户是某家庭家长，家庭名称为"旧名称"
When 用户在成员列表点击家庭名称区域，进入编辑，输入"新名称"保存
Then 家庭名称立即更新为"新名称"
And 所有家庭成员看到新名称
```

#### F2 邀请机制

**场景 1：家长邀请孩子生成邀请码**
```gherkin
Given 用户是家庭家长
When 用户点击"邀请成员" → "邀请孩子"，输入孩子姓名"小明"，选择展示模式"小学"，点击生成
Then 生成 6 位邀请码（数字 2-9，不含 0 和 1）
And 邀请码状态为"待使用"，记录在邀请列表中
And 邀请码有效期 24 小时
```

**场景 2：孩子输入正确邀请码加入**
```gherkin
Given 邀请码"123456"（实际为 2-9 数字）已生成，状态待使用，目标角色孩子
When 用户无家庭，在引导页点击"加入家庭"，输入邀请码，确认加入
Then 用户加入家庭，角色为孩子，孩子姓名为邀请时指定的名称
And 邀请码状态变为"已使用"，不可再次使用
And 跳转到日历视图
```

**场景 3：邀请码已过期**
```gherkin
Given 邀请码生成已超过 24 小时，状态待使用
When 用户输入该邀请码确认加入
Then 提示"邀请码已失效，请联系家长重新获取"
And 加入失败
```

**场景 4：邀请码已被使用**
```gherkin
Given 邀请码已被使用
When 用户再次输入该邀请码确认加入
Then 提示"邀请码已被使用"
And 加入失败
```

**场景 5：家长撤销待使用邀请码**
```gherkin
Given 邀请码待使用，邀请人是当前用户
When 用户在邀请列表点击"撤销"
Then 邀请码变为"已撤销"
And 该邀请码不可再使用
When 他人输入该邀请码
Then 提示"邀请码已被撤销"
```

**场景 6：家庭已满 10 人，拒绝新成员加入**
```gherkin
Given 家庭已有 10 名成员
When 被邀请人输入有效邀请码确认加入
Then 提示"家庭已满（10 人），无法加入"
And 加入失败
```

#### F3 成员管理

**场景 1：家长移除孩子成员**
```gherkin
Given 家庭有家长 A 和孩子 B，A 是家长
When A 在成员列表点击 B，点击"移除成员"，确认移除
Then B 被移除出家庭
And B 进入无家庭状态
And B 的历史打卡记录保留，但标记为已离群
```

**场景 2：已注销成员处理**
```gherkin
Given 成员 A 注销了账户
When 注销未超过 30 天
Then 成员列表中显示为"已注销成员"，灰色，不可交互
And 不占用家庭人数名额
When 注销已超过 30 天
Then 该成员从成员列表中移除
And 若已注销成员是创建者且家庭还有其他家长，则创建者身份自动转让给加入最早的家长
```

**场景 3：转让创建者**
```gherkin
Given A 是创建者（家长），家庭有其他家长 B
When A 点击 B，选择"转让创建者"，二次确认
Then A 变为普通家长
And B 成为新创建者
```

**场景 4：最后一个家长试图退出，家庭仍有孩子**
```gherkin
Given 家庭只有一个家长 A，还有 2 个孩子
When A 尝试执行退出家庭操作
Then 提示"请先将孩子移除或转让家庭给其他家长，才能退出"
And 退出操作被阻止
```

#### F4 孩子展示模式

**场景 1：家长设置孩子展示模式**
```gherkin
Given 家长点击孩子成员，选择"设置展示模式"
When 家长选择"小学模式"，点击保存
Then 该孩子的展示模式立即更新为小学模式
And 孩子端下次打开界面按新模式渲染
```

#### F5 多家庭切换

**场景 1：用户属于多个家庭，切换家庭**
```gherkin
Given 用户属于两个家庭，当前在家庭 A，上次查看是周视图，日期周一
When 用户在"我的"页面点击"切换家庭"，选择家庭 B
Then 切换到家庭 B
And 恢复家庭 B 上次记忆的视图和日期
And 跳转到日历视图
```

**场景 2：被移除后切换**
```gherkin
Given 用户被移除出家庭 A，用户仍有家庭 B
When 用户在切换列表点击家庭 A
Then 提示"你已不在该家庭中"
And 家庭 A 从切换列表中移除
```

**场景 3：用户只有一个家庭**
```gherkin
Given 用户只加入了一个家庭
Then "我的"页面中"切换家庭"菜单项隐藏或置灰
```

#### F6 退出解散恢复

**场景 1：创建者解散家庭**
```gherkin
Given A 是家庭创建者
When A 在成员列表底部点击"解散家庭"，输入正确家庭名称确认
Then 家庭状态变为"已解散"
And 所有成员进入无家庭状态
And 数据标记为待删除，保留 30 天
```

**场景 2：解散后 30 天内恢复**
```gherkin
Given 家庭已解散，还在 30 天保留期内
When 任意原成员登录，看到恢复提示，点击"恢复家庭"
Then 家庭恢复正常状态
And 所有成员关系和数据完整恢复
And 创建者身份不变
```

**场景 3：超过 30 天试图恢复**
```gherkin
Given 家庭已解散超过 30 天，数据已永久删除
When 用户试图恢复
Then 提示"数据已过期删除，无法恢复"
And 恢复失败
```

**场景 4：创建者试图直接退出家庭**
```gherkin
Given A 是家庭创建者，家庭还有其他成员
When A 尝试执行退出家庭操作
Then 提示"创建者无法退出，请先解散家庭"
And 退出操作被阻止
```

## 7. 业务概念模型

核心实体（概念层面）：

- **家庭**：名称、创建者、创建时间、状态（正常/已解散）
- **家庭成员**：关联用户 + 家庭、角色（家长/孩子）、孩子展示模式、加入时间
- **邀请码**：编码、家庭ID、目标角色、孩子姓名、展示模式、创建时间、过期时间、状态（待使用/已使用/已撤销/过期）、创建者ID

## 8. 非功能需求

- **性能**：成员列表加载 ≤ 500ms，邀请码验证 ≤ 1s
- **兼容性**：微信小程序基础库 ≥ 2.10.0，iOS 12+ / Android 8.0+
- **安全性**：数据按家庭隔离，非家庭成员无法访问任何家庭数据；敏感操作（解散/移除）需要二次确认
- **可用性**：所有异常场景（过期邀请码、错误邀请码等）给出清晰中文提示

## 9. 分期规划

### 第一期（当前）

Must 全部完成：
- 家庭创建、修改名称
- 双轨邀请机制（微信分享卡片 + 邀请码）
- 成员管理（移除、转让创建者、已注销处理）
- 孩子展示模式设置功能（存储设置，第一期统一小学模式渲染）
- 多家庭切换 + 状态记忆
- 退出解散 + 30 天恢复

不做（延后）：
- 成员搜索
- 解散推送订阅消息通知
- 差异化展示模式 UI 渲染（第二期）
