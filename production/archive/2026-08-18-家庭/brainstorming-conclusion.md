# 头脑风暴结论 · 家庭管理模块

## 用户角色及权限差异

| 角色 | 权限 |
|------|------|
| **家长** | 创建家庭、邀请成员、修改家庭名称、管理成员（移除/设置展示模式）、转让创建者、解散家庭、多家庭切换、管理日程 |
| **孩子** | 查看日程、打卡执行、查看个人统计、退出家庭（需家长先移除） |

- 一个用户可属于多个家庭，在不同家庭可拥有不同角色
- 孩子只建议属于一个家庭（技术不限制，但产品推荐）

## 功能边界

### Must 做（第一期必须实现）

| 模块 | 功能点 |
|------|--------|
| 家庭创建 | ✓ 创建家庭（自选角色：家长/孩子）、修改家庭名称（家长权限）、初始空态提示 |
| 邀请机制 | ✓ 双轨邀请：微信分享卡片（家长）+ 6 位邀请码（孩子）；邀请码有效期 24 小时一次性可撤销；邀请码指定角色，加入者不可更改 |
| 成员管理 | ✓ 成员列表按角色分组、查看成员详情、移除成员（家长权限）、转让创建者（仅限转给其他家长）、已注销成员 30 天缓冲处理、孩子姓名家庭内覆盖微信昵称显示 |
| 孩子展示模式 | ✓ 家长可为每个孩子设置三种展示模式之一（学龄前/小学/高年级）；第一期统一使用小学模式渲染，差异化 UI 第二期实现 |
| 多家庭切换 | ✓ 切换列表、状态记忆（上次视图/上次日期/筛选条件）、切换后恢复状态 |
| 退出解散恢复 | ✓ 非创建者可退出、创建者可解散（30 天恢复期）、任意原成员可在 30 天内恢复、到期自动删除 |

### Should 做（本期可延后，但需求明确）

- 无（所有 Must 已覆盖核心流程）

### Could 做（可选，未来版本）

- 成员搜索（家庭上限 10 人，本期不需要）
- 解散后订阅消息通知所有成员（本期不需要）

### 不做（本期明确排除）

- 家庭封面图片自定义（本期不需要，只保留名称）
- 家庭成员备注功能（孩子姓名由邀请人指定，已满足需求）
- 批量邀请（一次一个足够，上限 10 人）

## 核心业务场景与流程

1. **首次使用流程**：登录 → 引导页 → 创建家庭/加入家庭 → 日历视图
2. **邀请家长流程**：家长 → 成员列表 → 邀请成员 → 分享微信卡片 → 被邀请人点击 → 确认加入 → 成功
3. **邀请孩子流程**：家长 → 成员列表 → 邀请成员 → 输入孩子姓名 + 选择展示模式 → 生成邀请码 → 孩子输入邀请码 → 确认加入 → 成功
4. **解散恢复流程**：创建者 → 成员列表 → 解散家庭 → 输入名称确认 → 所有成员退出 → 30 天内任意原成员可恢复 → 到期永久删除

## 优先级判断

| 模块 | 优先级 |
|------|--------|
| 家庭创建 + 首次引导 | Must |
| 双轨邀请机制 | Must |
| 成员列表与基础管理 | Must |
| 孩子展示模式设置 | Must |
| 多家庭切换与状态记忆 | Must |
| 退出解散与恢复 | Must |
| 转让创建者 | Must |
| 修改家庭名称 | Must |
| 已注销成员处理 | Must |
| 成员搜索 | Could（不做） |
| 解散通知推送 | Could（不做） |
