## 2. 用户角色

> 引用 [index.md §2 用户角色](../../requirements/index.md#2-用户角色)。

本模块涉及的用户角色：

| 角色 | 本模块中的差异 |
|------|---------------|
| 家长 | 完整权限：登录、资料管理、"我的"页面所有入口（含创建/加入/切换家庭）、账户注销 |
| 孩子 | 受限权限：登录、资料管理、"我的"页面（无创建/加入/切换家庭入口 -- 由家庭模块控制）、账户注销 |
| 未登录用户 | 仅可见隐私政策弹窗和拒绝后的静态提示页，无法使用任何功能 |

**权限差异关键决策**：孩子端的"我的"页面是否展示创建/加入家庭入口，由家庭模块的角色判断决定（孩子在家庭中无权创建/加入家庭），认证模块不做角色判断，仅提供页面容器，由各入口方（家庭模块）自行校验权限。

## 3. 功能模块（用户故事 + GWT + 优先级）

### 3.1 功能模块总览

> 各模块详细功能描述见 [原有文档 §2-§8](../../requirements/module-auth.md)。

本章按功能域拆分为 7 组用户故事，每组含 GWT 验收标准、显式优先级、边界异常。

### 3.2 US1: 隐私政策同意

**优先级：Must**
**关联原有文档**：[§3.2 隐私政策弹窗](../../requirements/module-auth.md#32-隐私政策弹窗)

| 场景 | GIVEN | WHEN | THEN |
|------|-------|------|------|
| 首次打开-展示弹窗 | 用户首次打开小程序 AND 未缓存同意状态 | 应用初始化 | 展示隐私政策弹窗（含政策内容链接 + 勾选框 + 同意/不同意按钮） |
| 未勾选-同意置灰 | 隐私政策弹窗展示 AND 用户未勾选"我已阅读并同意" | 用户点击"同意并继续" | 按钮置灰，不触发任何操作 |
| 已勾选-同意继续 | 隐私政策弹窗展示 AND 用户已勾选 | 用户点击"同意并继续" | 本地缓存同意状态 → 开始 wx.login 流程 |
| 拒绝隐私政策 | 隐私政策弹窗展示 | 用户点击"不同意" | 跳转静态提示页"需要同意隐私政策才能使用"，不调用任何 API |
| 再次打开-跳过弹窗 | 用户之前已同意隐私政策 AND 缓存未清除 | 应用初始化 | 跳过隐私政策弹窗，直接走登录流程 |
| 隐私政策链接不可达 | 弹窗中政策链接被点击 | 网络不可用或链接失效 | 提示"暂时无法加载，请稍后查看"（不阻断流程，用户仍可勾选同意） |

**补充边界异常**：

| 场景 | 原有文档覆盖 | 补充说明 |
|------|:--------:|---------|
| 用户在勾选前关闭小程序 | 未覆盖 | 需补充：关闭即视为未同意，下次打开重新展示弹窗 |
| 小程序升级后隐私政策变更 | 未覆盖 | 需补充：隐私政策版本号机制，版本更新后所有用户需重新同意（即使之前已同意旧版） |
| 隐私政策内容为空或加载失败 | 已覆盖（链接不可达） | 弹窗中嵌入的文本摘要与链接解耦，摘要静态内嵌于小程序包中，不依赖网络 |

### 3.3 US2: 微信静默登录

**优先级：Must**
**关联原有文档**：[§2 认证方式设计](../../requirements/module-auth.md#2-认证方式设计)

| 场景 | GIVEN | WHEN | THEN |
|------|-------|------|------|
| 正常登录 | 用户已同意隐私政策 | wx.login 成功返回 code → 后端 jscode2session 换取 openid | 查找或创建账户 → 签发 JWT → 前端存储到 Storage → 进入下一流程 |
| wx.login 失败 | 微信服务异常或网络不可用 | wx.login 返回失败 | 展示"登录失败，请检查网络后重试" + 重试按钮；不进入后续流程 |
| 后端换 openid 超时 | code 已获取 | 后端调用微信 API 超时（>5s） | 自动重试 1 次 → 仍失败则返回前端提示"服务繁忙，请稍后重试" |
| 新用户自动创建账户 | 后端未找到对应 openid 的用户 | 后端自动创建账户（含默认昵称"微信用户"、默认头像、创建时间） | 返回新 userId + JWT |
| Storage 清除后重新登录 | 用户清除微信 Storage 导致 Token 丢失 | 用户打开小程序 | 重新走完整登录流程，用户无感知（wx.login 静默完成） |
| 微信账号切换 | 用户在微信中切换了账号 | wx.login 返回新 openid | 后端查找新 openid → 有则返回已有账户、无则创建新账户 |

**补充边界异常**：

| 场景 | 处理 |
|------|------|
| 并发登录请求（短时间内多次触发 wx.login） | 前端加锁，只执行一次 wx.login，重复调用直接返回 pending 的 Promise |
| 微信 API 返回错误码（非超时，如 code 已使用） | 重新调用 wx.login 获取新 code 后重试，最多 1 次 |
| JWT 签发时密钥不可用 | 后端返回 500，前端提示"服务异常，请稍后重试" |

### 3.4 US3: 昵称头像收集

**优先级：Should**
**关联原有文档**：[§2.3 昵称头像收集](../../requirements/module-auth.md#23-昵称头像收集) + [§3.3 昵称头像收集页](../../requirements/module-auth.md#33-昵称头像收集页)

| 场景 | GIVEN | WHEN | THEN |
|------|-------|------|------|
| 首次展示收集页 | 用户首次登录 AND 尚未设置过昵称头像（使用默认值） | 登录成功 | 展示收集页：默认头像占位图 + 昵称输入框（微信原生控件，预填微信昵称） + "开始使用"按钮 |
| 设置头像 | 收集页展示 | 用户点击头像区域 | 弹出微信头像选择器（open-type="chooseAvatar"） → 选择后实时预览 |
| 设置昵称 | 收集页展示 | 用户点击昵称输入框 | 弹出微信昵称面板（type="nickname"），预填当前微信昵称 → 用户确认后回填 |
| 跳过收集 | 收集页展示 | 用户点击"开始使用" | 使用默认值（昵称"微信用户" + 灰色默认头像占位图）→ 进入下一流程 |
| 再次登录-不展示 | 用户之前已设置或跳过昵称头像 | 再次登录 | 跳过收集页，直接进入主流程 |
| 提交时网络异常 | 用户已选择头像和昵称 | 点击"开始使用"时网络不可用 | 本地暂存修改内容 → 网络恢复后自动补传 → 期间用户可正常使用（显示本地暂存值） |

### 3.5 US4: 登录态管理

**优先级：Must**
**关联原有文档**：[§4 登录态管理](../../requirements/module-auth.md#4-登录态管理)

| 场景 | GIVEN | WHEN | THEN |
|------|-------|------|------|
| 请求携带 Token | 用户已登录 AND JWT 存储在 Storage | 发起任意 API 请求 | 请求拦截器自动从 Storage 读取 JWT 写入 `Authorization: Bearer <jwt>` Header |
| 静默续期 | API 返回 401 | 响应拦截器捕获 401 | wx.login → 后端换新 JWT → 更新 Storage → 重放原请求。用户无感知 |
| 并发 401 续期锁 | 多个 API 同时返回 401 | 响应拦截器检测到续期正在进行 | 后续请求等待首个续期 Promise 完成 → 使用新 Token 重放各自请求 |
| 续期时网络异常 | API 返回 401 触发续期 | wx.login 或续期接口因网络异常失败 | 提示"网络异常，请检查网络" + 重试按钮；清除旧 Token |
| 续期时 wx.login 失败 | API 返回 401 触发续期 | wx.login 返回失败（非网络原因） | 提示"登录已过期，请重新打开小程序" + 清除 Token |
| Token 被篡改 | 前端携带被篡改的 JWT | 后端验签失败返回 401 | 触发静默续期流程（同正常 401） |
| Storage 满无法写入 | 续期获取新 JWT | wx.setStorageSync 因 Storage 满写入失败 | 提示"存储空间不足，请清理微信缓存" |

**补充边界异常**：

| 场景 | 原有文档覆盖 | 补充说明 |
|------|:--------:|---------|
| JWT 过期前一刻请求正好发出 | 未明确 | 补充：后端在 exp 前 5 分钟内一视同仁返回 401（不依赖客户端提前刷新），由客户端续期。避免时间偏差导致的有效 Token 被拒绝。 |
| 后端时钟偏差 | 未覆盖 | 补充：JWT exp 校验允许 30 秒时钟偏差容忍 |
| 续期接口频率限制触发（每用户每分钟 >10 次） | 未覆盖 | 补充：前端续期失败后等待 60 秒再重试，避免连续触发频率限制 |

### 3.6 US5: 用户资料查看与编辑

**优先级：Should**
**关联原有文档**：[§5 用户资料](../../requirements/module-auth.md#5-用户资料)

| 场景 | GIVEN | WHEN | THEN |
|------|-------|------|------|
| 进入编辑页 | 用户处于"我的"页面 | 点击头像/昵称区域 | 进入编辑页：显示当前头像（可更换）+ 当前昵称（可修改）+ 保存按钮 |
| 修改头像 | 编辑页展示 | 用户点击"更换头像" → 微信选择器选择新头像 | 头像实时预览 → 点击保存后上传 → 返回"我的"页面并刷新 |
| 修改昵称 | 编辑页展示 | 用户修改昵称内容 | 点击保存后提交 → 返回"我的"页面并刷新 |
| 昵称为空 | 编辑页展示 | 用户清空昵称后点击保存 | 前端拦截，提示"昵称不能为空" |
| 昵称过长 | 编辑页展示 | 用户输入 >20 字符 | 输入框限制长度（maxlength=20），后端二次校验 |
| 昵称含敏感词 | 编辑页展示 | 用户输入含敏感词的昵称并保存 | 后端校验 → 拒绝保存 → 提示"昵称包含不允许的词汇" |
| 保存时网络异常 | 编辑页展示 AND 用户修改了内容 | 点击保存时网络不可用 | 提示"保存失败，请检查网络" + 保留用户输入内容不清空 |
| 头像上传失败 | 编辑页展示 AND 用户修改了头像 | 头像上传接口返回失败 | 提示"头像上传失败，请重试" + 不同时保存昵称修改（事务一致性） |

### 3.7 US6: "我的"页面

**优先级：Should**
**关联原有文档**：[§6 "我的"页面](../../requirements/module-auth.md#6-我的页面)

| 场景 | GIVEN | WHEN | THEN |
|------|-------|------|------|
| 有家庭-完整展示 | 用户属于至少 1 个家庭 | 进入"我的"页面 | 显示：头像昵称区 + 当前家庭信息（名称+角色）+ 切换家庭（≥2 个时）+ 创建家庭 + 加入家庭 + 设置 |
| 无家庭-简化展示 | 用户不属于任何家庭 | 进入"我的"页面 | 显示：头像昵称区 + 创建家庭 + 加入家庭 + 设置。不显示家庭信息区和切换家庭入口 |
| 点击头像区 | 任意状态 | 点击头像/昵称区域 | 跳转编辑资料页（认证模块） |
| 点击当前家庭 | 有家庭状态 | 点击当前家庭信息行 | 跳转家庭模块 → 成员列表页（传递当前 familyId） |
| 点击创建家庭 | 任意状态 | 点击"创建家庭" | 跳转家庭模块 → 创建流程 |
| 点击加入家庭 | 任意状态 | 点击"加入家庭" | 跳转家庭模块 → 邀请码输入页 |
| 点击切换家庭 | ≥2 个家庭 | 点击"切换家庭" | 跳转家庭模块 → 切换面板 |
| 点击设置 | 任意状态 | 点击"设置" | 进入设置页面（预留：关于、注销等） |

**补充边界异常**：

| 场景 | 处理 |
|------|------|
| "我的"页面加载时网络异常 | 头像昵称区使用本地缓存展示，家庭信息区显示"加载失败"占位；基本入口（创建/加入/设置）仍可点击 |
| 用户同时在另一设备解散了当前家庭 | 下次进入"我的"页面时重新加载家庭列表，自动切换显示为"无家庭"模式 |

### 3.8 US7: 账户注销

**优先级：Should**
**关联原有文档**：[§7 账户注销](../../requirements/module-auth.md#7-账户注销)

| 场景 | GIVEN | WHEN | THEN |
|------|-------|------|------|
| 满足条件-正常注销 | 用户满足注销条件（无家庭关联） | 进入设置 → 注销账户 → 阅读说明 → 确认 → 二次确认 | 后端标记账户"已注销" → 清除本地 Token → 关闭小程序 |
| 属于家庭-拦截 | 用户属于至少 1 个家庭 | 进入注销流程 | 提示"请先退出所有家庭后再注销" + 跳转家庭管理页 |
| 30 天内恢复 | 账户已注销 AND 距注销 <30 天 | 用户重新打开小程序 → wx.login | 显示恢复页面："你的账户已申请注销，数据保留至 YYYY-MM-DD（剩余 N 天）" + "恢复账户"按钮 + "知道了"按钮 |
| 恢复账户-确认恢复 | 恢复页面展示 | 用户点击"恢复账户" | 后端恢复账户状态 → 签发新 JWT → 进入正常使用 |
| 恢复账户-保持注销 | 恢复页面展示 | 用户点击"知道了" | 关闭小程序，保持已注销状态 |
| 30 天后重新登录 | 账户已注销 AND 距注销 ≥30 天 | 用户重新打开小程序 → wx.login | 后端发现账户已过期删除 → 创建全新账户（同新用户流程） |
| 注销时网络异常 | 用户点击"确定注销" | 网络不可用 | 保持原状态，提示"操作失败，请重试"，不改变本地状态 |

**补充边界异常**：

| 场景 | 原有文档覆盖 | 补充说明 |
|------|:--------:|---------|
| 注销中再次登录（并发） | 未覆盖 | 补充：后端注销接口幂等，已注销的账户再次发送注销请求直接返回成功 |
| 30 天缓冲期内，用户在另一设备恢复账户 | 未覆盖 | 补充：另一设备恢复后，本设备下次请求时 Token 有效（后端已恢复），正常使用 |
| 注销后打卡记录匿名化的一致性 | 已覆盖（打卡记录匿名化保留） | 补充：匿名化规则——移除打卡记录中 userId 关联，替换为匿名标识符（如 `deleted_user_001`），保留时间戳和日程 ID |

## 7. 业务概念模型

> 引用 [原有文档 §5.1 资料模型](../../requirements/module-auth.md#51-资料模型)。

本模块涉及的业务实体：

| 实体 | 概念描述 | 生命周期 |
|------|---------|---------|
| 用户账户（User Account） | 通过微信 openid 唯一标识的个人账户，含昵称/头像/创建时间/最后登录时间 | 创建（首次 wx.login）→ 活跃 → 注销（30 天缓冲）→ 永久删除 |
| 微信身份（WeChat Identity） | 微信 openid + session_key，由微信服务端管理，本模块仅持有 openid 作为用户标识 | 与微信账号绑定 |
| JWT Token | 登录凭证，含 userId/iat/exp，7 天有效期，静默续期 | 签发 → 有效 → 过期/401 续期 → 新 Token |
| 隐私同意记录 | 用户对隐私政策的同意状态及版本号 | 首次同意记录 → 政策更新后需重新同意 |
| 注销记录 | 账户注销时间、30 天到期时间、恢复状态 | 注销标记 → 30 天倒计时 → 到期删除或恢复 |

## 8. 非功能需求

> 引用 [原有文档 §4.7 安全边界](../../requirements/module-auth.md#47-安全边界) + [index.md §8 非功能需求](../../requirements/index.md#8-非功能需求)。

**补充本模块特有的非功能需求：**

| 类别 | 需求 | 指标 | 优先级 |
|------|------|------|:--:|
| 性能 | 登录流程（隐私政策到 JWT 签发）完成时间 | ≤ 3 秒（含微信 API 调用） | Must |
| 性能 | JWT 续期完成时间 | ≤ 2 秒（静默，用户无感知） | Must |
| 性能 | "我的"页面加载 | ≤ 500ms | Should |
| 安全 | JWT 签名密钥管理 | 环境变量注入，不进源码 | Must |
| 安全 | 登录/续期接口频率限制 | 每用户每分钟 ≤ 10 次 | Must |
| 安全 | openid 客户端不可见 | 前端不解码 JWT，不记录到日志 | Must |
| 可用性 | 隐私政策弹窗 | 所有用户首次必见，操作不超过 2 步（勾选+同意） | Must |
| 可用性 | 昵称头像收集 | 可一键跳过，不强制 | Should |
| 可用性 | 注销流程 | 最多 3 步（进入设置 → 阅读说明 → 二次确认） | Should |
| 兼容性 | 微信基础库 | ≥ 2.10.0（nickname input 和 chooseAvatar 支持的最低版本） | Must |
| 数据 | 注销后个人资料 | 保留 30 天，到期永久删除（不可恢复） | Must |
