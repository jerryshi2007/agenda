# auth-deletion · 账户注销与 30 天缓冲恢复

## ADDED Requirements

### Requirement: 注销条件检查
系统 MUST 在用户发起注销前检查家庭关联状态。属于任一家庭的用户 MUST 先退出所有家庭后方可注销。

#### Scenario: 满足条件可正常注销
- **WHEN** 用户满足注销条件（不属于任何家庭）AND 进入注销流程
- **THEN** 系统允许进入注销流程

#### Scenario: 属于家庭时拦截
- **WHEN** 用户属于至少 1 个家庭 AND 进入注销流程
- **THEN** 提示"请先退出所有家庭后再注销"，提供跳转家庭管理页的入口

### Requirement: 注销流程
注销流程 MUST 包含说明页、确认、二次确认三步。确认后 MUST 清除本地 Token 并关闭小程序。注销接口 MUST 幂等。

#### Scenario: 正常注销流程
- **WHEN** 用户满足注销条件 AND 进入设置 → 注销账户 → 阅读说明 → 确认 → 二次确认
- **THEN** 后端标记账户"已注销"（记录注销时间 + 30 天到期时间 + 恢复状态）→ 清除本地 Token → 关闭小程序

#### Scenario: 注销时网络异常
- **WHEN** 用户点击"确定注销" AND 网络不可用
- **THEN** 保持原状态，提示"操作失败，请重试"，不改变本地状态

#### Scenario: 注销接口幂等
- **WHEN** 已注销的账户再次发送注销请求
- **THEN** 后端直接返回成功，不产生副作用

### Requirement: 30 天缓冲恢复
注销后 30 天内，用户重新打开小程序时 MUST 展示恢复页面，含倒计时信息和"恢复账户"、"知道了"两个操作按钮。

#### Scenario: 30 天缓冲期内登录展示恢复页
- **WHEN** 账户已注销 AND 距注销 <30 天 AND 用户重新打开小程序 → wx.login
- **THEN** 显示恢复页面："你的账户已申请注销，数据保留至 YYYY-MM-DD（剩余 N 天）" + "恢复账户"按钮 + "知道了"按钮

#### Scenario: 恢复账户
- **WHEN** 恢复页面展示 AND 用户点击"恢复账户"
- **THEN** 后端恢复账户状态 → 签发新 JWT → 进入正常使用

#### Scenario: 保持注销
- **WHEN** 恢复页面展示 AND 用户点击"知道了"
- **THEN** 关闭小程序，保持已注销状态

#### Scenario: 另一设备恢复账户后本设备继续使用
- **WHEN** 用户在另一设备恢复了账户 AND 本设备发起 API 请求携带旧 Token
- **THEN** 后端 Token 有效（账户已恢复），请求正常处理

### Requirement: 30 天到期永久删除
注销 30 天到期后，系统 MUST 永久删除用户个人资料（昵称、头像、openid），打卡记录 MUST 匿名化保留。<br>30 天到期后再次登录 MUST 视为新用户。

#### Scenario: 30 天到期后重新登录
- **WHEN** 账户已注销 AND 距注销 ≥30 天 AND 用户重新打开小程序 → wx.login
- **THEN** 后端发现账户已过期删除，创建全新账户（同新用户流程）

#### Scenario: 打卡记录匿名化
- **WHEN** 账户 30 天到期被永久删除
- **THEN** 系统移除打卡记录中 userId 关联，替换为匿名标识符（如 `deleted_user_001`），保留时间戳和日程 ID
