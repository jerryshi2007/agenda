# dev-verification · 验证纪律

## 铁律

```
无新鲜验证证据不做完成声明
```

如果你在本轮对话中没有运行验证命令，你不能声称它通过。

## Gate 函数

```
声称任何状态前：
1. 识别 → 什么命令能证明这个声明？
2. 运行 → 执行完整命令（新鲜运行，非上一次的结果）
3. 读取 → 看完整输出、检查退出码、数失败数
4. 验证 → 输出是否真的支持声明？
   - 否 → 如实报告实际状态（"构建失败，3 errors"）
   - 是 → 声明 + 附带证据（"全部通过，58/58"）
5. 声明 → 仅在以上步骤完成后

跳过任一步骤 = 在撒谎，不是在验证
```

## 各技术栈验证命令

| 技术栈 | 测试 | 构建 | 类型检查 | Lint |
|--------|------|------|----------|------|
| .NET | `dotnet test` | `dotnet build` | — | `dotnet format --verify-no-changes` |
| Vue 3 | `pnpm test run` | `pnpm build` | `pnpm vue-tsc --noEmit` | `pnpm lint` |

## Red Flags——STOP

- 使用"应该""大概""看起来"等词
- 在验证之前表达满意（"好了！""完成了！"）
- 信任 agent 的成功报告
- 依赖部分验证
- 想"就这一次"
- 累了想快点结束

## 常见错误

| 错误 | 正确 |
|------|------|
| "测试应该通过了" | 跑 `dotnet test`，看到输出，说"34/34 passed" |
| "构建没问题" | 跑 `dotnet build`，看到 exit 0，说"Build succeeded" |
| Agent 说成功 | 检查 VCS diff、跑验证命令、确认实际状态 |
| 上次跑过了 | 代码改了，重新跑 |

## 适用时机

- 声称完成、修好、通过的任何时候
- 提交前、PR 前
- 任务完成、移交给下一阶段前
- 表达任何形式的满意之前
