# git-commit · 提交规范

## 约束

- **动词开头**——摘要用祈使句动词开头（add / fix / refactor / docs），与代码行为一致。
- **一行摘要 + 空行 + 详情**——首行 ≤50 字符概括，空行后写动机/影响/注意事项。摘要过长则范围不清。
- **一事一提交**——一个提交只含一个逻辑变更；混合多变更无法独立回滚或 review。
- **不直推 main**——改动走分支/PR，main 保持稳定。
- **不 force push 共享分支**——共享分支强推会覆盖他人提交；仅个人分支可强推。
- **密钥管理见 `dev-security` rule**。git 层面配合 .gitignore 确保敏感文件不被追踪。

## 示例

- ✅
  ```
  fix: 用户锁定后仍可重置密码

  锁定检查在密码校验前，导致锁定账号走"忘记密码"流程时绕过锁定。
  改为重置前先校验账号锁定状态。修复 #1234。
  ```
- ❌ `update` / `fix bug` / `some changes`（无动词意图、无详情）
- ❌ 一个提交同时含新功能 + bug 修复 + 格式化（多事一提交）
